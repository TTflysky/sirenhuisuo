# 太极执行架构路线

## 当前定位

太极是本地优先的桌面多智能体工作台。当前 Electron 主进程负责本机工具、连接器和窗口，React 负责交互；任务状态仍主要保存在渲染进程 `localStorage` 中。

说明书中的 FastAPI、Postgres、Redis、Vault 和 Temporal 是未来需要远程多机协作时的基础设施选项，不在第一阶段全部引入。

## 已完成

### v0.12.0：任务合同与 Plan 基础层

- `TaskContract` 固定原始目标、不可丢失约束、完成标准、证据要求和用户待提供条件。
- `TaskPlan` 固定版本、步骤、依赖、输出格式、重试策略、幂等键、补偿步骤和审批标记。
- 计划校验拒绝重复步骤、缺失依赖、循环依赖、无输出规范和无幂等键的副作用步骤。
- Plan 可以序列化和重新解析，作为后续持久化、恢复和回放的共同格式。

## 下一步顺序

1. 用 SQLite 持久化 task、contract、plan、step、event 和 approval；保留 localStorage 迁移入口。
2. 将团队任务从旧的步骤对象迁移到版本化 Plan，并让 Runner 只执行通过校验的步骤。
3. 为工具、连接器和 Skill 统一实现 `validateInput -> dryRun -> call -> validateOutput` 适配器协议。
4. 增加幂等执行记录、指数退避、补偿步骤、审批等待和取消状态。
5. 增加 trace、结构化审计、token/cost 统计和完整任务回放。
6. 只有在需要跨电脑后台执行或多人同时访问时，再拆出 FastAPI、Postgres、队列和远程 Worker。

## 不可破坏的边界

- LLM 只能提出合同和计划，不能直接宣布步骤完成。
- Runner 必须根据真实输出、证据和验收条件决定成功。
- 有副作用的步骤必须有幂等键；无法幂等时必须定义补偿或人工审批。
- 用户凭据、聊天记录、长期记忆和本地工作区不进入 GitHub。
