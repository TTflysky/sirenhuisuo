# 太极 V5 自我评分与交付成熟度评估

日期：2026-08-08

## 结论先行

V5 已经不再是只有提示词和界面的工作流外壳：项目、会话、团队提案、责任步骤、工作区、证据、恢复点和自适应计划已经有结构化内核。但是，V5 目前仍不应被称为“可稳定交付的自主智能体团队产品”。它更准确的定位是：**具备真实执行内核的工程 Beta，尚未完成端到端交付验收**。

综合评分：**6.2 / 10**。

这个分数不是对代码量的评价，而是对“用户给出一个真实目标后，团队能否自主完成、验证、交付并在异常后恢复”的评价。V5 的架构基础明显高于早期版本，但真实交付闭环仍有缺口。

## 本次 v5.10.3 完成内容

之前约 48 万 Token 的问题不是单次模型上下文窗口，而是任务多轮模型调用累计的执行预算。旧逻辑达到预算后直接写入 `blocked`，最终验收函数因此提前返回，造成“已经有产物但被判未完成”。

本次修复：

1. Token 预算达到上限进入 `checkpointed`，明确表示容量暂停，不是业务失败。
2. 有真实证据时仍允许完成最终验收；验收通过才进入 `completed`。
3. 没有足够证据时保存当前上下文、产物和未决问题，恢复后只处理剩余部分。
4. 恢复新周期时重置当前周期预算，但保留跨周期累计用量。
5. 团队成员和运行观察窗不再把容量暂停显示为成员失败。
6. 非 Token 的模型调用、工具调用等安全预算仍保持硬停止，防止无限循环。

## 已经完成但不能重复立项的能力

- 团队提案版本化、旧审批失效和当前 revision 批准绑定。
- 自适应计划图、依赖、换路线、局部返工和审查退回。
- 交付物驱动规划、任务合同、责任子任务和证据投影。
- 项目/对话/工作区隔离、长任务检查点和运行回放。

后续只做回归、闭环和真实验收，不重新开发这些已经存在的底座。

## 仍未达到交付标准的原因

### P0

- 没有两个不同类型的真实项目连续完成“规划→执行→审查→返工→交付→验收”。
- 能力缺口可以被报告，但尚未自动生成补员提案并安全恢复受影响节点。
- 原生执行器没有把计划中的独立 ready 节点实现为有限并行执行。
- 成员建立时的“初步规划”仍是结构化模板消息，不是每名成员基于目标和资料产生的真实规划。

### P1

- 真实客户端驻留、暂停/恢复和显卡环境仍缺少长时间压力证据。
- Electron UI 与已验收 HTML Demo 的一致性还需要安装包级截图回归。
- 安装包未签名，Windows SmartScreen 可能影响首次安装。

## V5 是否可以交付

**当前答案：不能作为稳定产品交付，可以作为内部工程 Beta 继续验证。**

可以交付的是“内核试运行版本”，不能承诺“给出任意复杂需求后必然自主完成”。在下列条件全部满足前，不应把 V5 宣称为最终产品：

1. 两个真实项目都产生可运行最终产物并通过独立验收。
2. 预算暂停、网络失败、工具失败、审查退回和客户端重启都能保留现场并继续。
3. 观察窗能清楚回答：谁在做什么、等待谁、为什么暂停、下一步是什么。
4. 真实项目回放中不再出现旧项目串台、错误成员审批残留或“有文件却失败”。

## 下一步，只补缺口

1. `v5.11`：把能力缺口接入现有团队提案 revision，并实现受影响节点的安全恢复。
2. `v5.12`：把独立 ready 节点做成有上限的有限并行，整合节点继续严格等待证据。
3. `v5.13`：让成员初步规划读取真实目标和交付物后生成，不再使用统一模板作为最终规划。
4. 两个真实项目完成后再重新评分；在此之前不追加装饰性功能。
