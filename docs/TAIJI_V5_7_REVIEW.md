# 太极 V5.7.0 版本复盘

日期：2026-08-07

## 本版结论

V5.7.0 已把自动 Skill 从“单次复盘直接生成 Markdown 草案”升级为受控生命周期：跨任务候选聚合、确定性编译、结构与安全验证、人工审批、灰度调用、失败自动停用和版本回滚。

这次改动解决的是项目经验如何成为可信能力，不是给历史问题增加关键词通道。模型仍负责理解任务和提出候选；内核只约束项目边界、来源证据、权限、验证、审批和运行状态。

## 完成项

- 新增持久化 `SkillCandidate` 账本。候选包含稳定 ID、项目 ID、来源任务和证据 ID、工具路线与指纹、独立任务数、成功率、失败模式、权限、风险、状态和完整观察记录。
- 单次任务只能形成候选观察。至少两个独立任务通过真实验收、工具路线相似度不低于 70%、失败率不高于 20%，才允许进入编译。
- 复盘模型不再输出完整 `SKILL.md` 或精确补丁，只输出步骤、输入、输出、成功标准、权限、外部依赖、正向样例和失败样例等结构化候选信息。
- 新增 Skill 编译器，生成只包含 `name` 和 `description` 的规范 frontmatter、简洁工作流、`references/contract.md` 和 `agents/openai.yaml`。核心规则保持精简，详细契约按需加载。
- 新增验证流水线：候选门槛、frontmatter、命名、渐进加载、敏感路径和凭据、工具权限、外部依赖、静态 Dry-run、正向样例和失败样例。任一硬检查失败都不会生成待审批草案。
- Skill 审批页升级为“学习与审批”，可查看正文、Diff、来源任务和证据、工具路线、权限、风险、验证报告和灰度阈值；未达门槛的候选单独展示积累进度。
- 批准后自动 Skill 先进入灰度。助理、员工私聊和团队工具调用均记录真实成功或失败；5 次调用且成功率不低于 80% 后转为启用，2 次失败或灰度成功率过低时自动停用。
- 每次批准的自动 Skill 都生成独立版本快照。更新只能替换太极自己生成的自动 Skill；内置和用户手动安装 Skill 继续受到保护。自动 Skill 可回滚到上一份批准版本。
- 自动 Skill 现在以完整目录和包清单安装，不再因缺少包清单被技能扫描误判为旧版单文件或不完整安装。
- 章北海内置人格升级至 v28，明确候选、编译、验证、审批、灰度、停用和回滚是不同状态，禁止把前置状态冒充为“已经学会并可用”。

## 未包含内容

- 没有提前实施 V5.8 的 20 至 30 个长期可回放任务、真实多窗口长驻和大员工量持续评测。
- 没有让模型自动批准或自动覆盖 Skill。高风险和外部副作用仍受原审批边界约束。
- 没有为某个 Skill 名称、网站、命令或用户措辞添加专用关键词分支。
- 本版没有打包客户端、覆盖本机安装或发布 GitHub；当前交付范围是源码、验证和版本文档。

## 失败样本与修正

- 初次验证对 Skill 包文件顺序作了不必要假设。修正为集合校验，文件顺序不再影响完整性判断。
- 编译器最初在通用安全说明中使用“账号/授权”措辞，被现有需求扫描正确识别为“使用前需要账号配置”。修正为不产生虚假依赖的“用户专属凭据/人工确认”，避免新生成 Skill 被错误标为待配置。
- 完整门禁首次被旧人格验收脚本中的 v26 断言阻塞。产品实际已经运行 v28，修正后将助理聊天、总设置和人格设置入口统一改为直接使用 `PERSONA_MIGRATION_APPENDIX_V28`，旧版本别名只保留兼容；图像路由和人格验收同时核对 V5.6、V5.7 协议确实进入当前人格。
- 这些问题属于验证与状态表达，不是模型理解问题；修正后重新通过完整生命周期回归。
