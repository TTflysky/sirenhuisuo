# 太极 v3.0 - v3.4 优化升级计划

基线：v2.9.5，工程能力 87/100，真实生产可用性 76/100。
总原则：模型负责理解、判断和重规划；运行时负责对象身份、安全边界、状态一致性、幂等、证据和可观测性。不得把每一次错误都做成新的硬编码对话通道。

## 阶段 A：v3.0 语义决策与供应商韧性

目标：让“理解用户当前真正要什么”和“模型暂时不可用”成为可验证的系统能力。

- 将语义基准扩展到至少 400 条，覆盖指代消解、并行目标、目标切换、纠错、暂停恢复、团队插话、指定资源和附件引用；按失败类别而非单句打补丁。
- 将任务决策拆为候选理解、上下文约束、风险/证据校验和可执行计划四层，保留每层输入与拒绝原因。
- 建立模型健康状态、熔断、退避、供应商切换建议和可控降级；区分“可稍后重试”“应换模型”“需要用户授权”。
- 为模型调用增加端到端预算、首字耗时、成功率、503/429/超时分布与恢复结果指标。

验收：400 条语义轨迹准确率不低于 98%，所有分类都有反例；人工注入 503、429、超时和网络中断时，任务现场可恢复且不会声称完成。

## 阶段 B：v3.1 外部能力真实验证矩阵

目标：让模型、图片、Skill、网页、MCP 与连接器的“可用”来源于真实调用证据。

- 建立可配置的测试账户矩阵：聊天模型、GPT Image、网页读取、SkillHub、知识库、邮件、GitHub 和通用 HTTP。
- 每类能力至少覆盖成功、缺配置、鉴权失败、限流、协议错误、内容无效和恢复七种状态。
- Skill 生命周期改为发现、读取规则、调用、产出、验收五段证据；安装成功不再等于调用成功。
- 指定 URL 保持原始对象身份；直连失败只能进入经过记录的读取替代，不得主题搜索替换正文。

验收：每类外部能力都有真实环境报告和脱敏证据；客户端只展示已经实际验证的能力状态。

## 阶段 C：v3.2 长任务、团队与客户端性能

目标：长时间任务能持续、可观察、可恢复，界面不会因规模增长失去可读性。

- 将 `hermesClient.ts`、`nativeExecutionAdapter.cjs`、`store.tsx` 按决策、执行、持久化、展示和 IPC 继续拆分，并保持现有边界门禁。
- 进行 8 小时 Electron 驻留、多窗口反复开关、后台驻留、任务恢复、320+ 员工和高频事件压测；单列 GPU 降级路径和崩溃归因。
- 优化聊天流、任务看板与日志投影，只增量渲染当前项目和当前阶段；修复无效动态导入并切分主包。
- 团队任务对每个阶段显示负责人、证据、耗时、等待条件和下一步；恢复只恢复责任步骤，不复制项目卡片。

验收：8 小时报告无持续内存增长、无任务丢失；12 窗口和高频事件下界面保持响应；主包与首屏指标相对 v2.9.5 明确下降。

## 阶段 D：v3.3 发布、迁移与安全演练

目标：每个正式版本能可靠下载、安装、迁移、验证和回滚。

- 用真实已发布旧版本执行更新发现、下载校验、迁移、启动验证、故障注入、回滚和业务数据对账。
- 统一发布门禁：版本、锁文件、README、变更说明、交接、人格版本、SBOM、来源证明、标签、安装包和远端哈希必须同一提交可追溯。
- 评估 Windows 代码签名、更新源可信校验和依赖审计；将在线审计不可用明确标成未验证状态。
- 为凭据增加轮换、过期提醒、最小权限检查和可导出的脱敏审计记录。

验收：至少两轮旧版到新版的成功升级和一轮故障回滚完成，任务、团队、记忆、模型配置和工作区均一致；发布资产可从 GitHub 独立下载并校验。

## 阶段 E：v3.4 面向真实项目的专业协作

目标：把“拉团队”升级为可连续交付的软件项目协作。

- 用真实软件需求跑产品、架构、UX/UI、前端、后端、测试、审查、交付全链路，沉淀可复用项目模板而不是固定聊天脚本。
- 让章北海只承担协调、追问、合并与用户沟通；专家成员只对职责工件和验收负责。
- 引入项目级风险登记、依赖阻塞、变更影响分析、可追溯决策记录和阶段性交付物。
- 建立用户可复现的验收包：需求、计划、Diff、构建、测试、审查意见、产物和未决风险。

验收：连续完成至少 3 个不同类型的真实项目；审查退回只影响责任阶段，用户可从项目看板理解项目状态和交付质量。

## 阶段顺序与发布策略

1. 阶段 A 完成后发布 v3.0，先验证语义与模型韧性。
2. 阶段 B 完成后发布 v3.1，补齐外部生态的真实证据。
3. 阶段 C 完成后发布 v3.2，解决长期运行和可维护性。
4. 阶段 D 完成后发布 v3.3，取得可信升级与回滚能力。
5. 阶段 E 完成后发布 v3.4，以真实项目验收检验团队协作。

每一阶段结束必须同步：内置人格、交接手册、差异矩阵、自我评价、测试证据和发布资料。小版本仅用于本地验证与源码同步；阶段验收通过后再发布客户端与 GitHub Release。
