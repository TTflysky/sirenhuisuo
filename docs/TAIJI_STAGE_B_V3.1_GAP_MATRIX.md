# 太极 v3.1 阶段 B 差异矩阵

评估日期：2026-08-01
基线：v3.0.0
目标：让外部能力的“可用”来自真实调用和有效响应，而不是配置存在、工具被发现或模型口头声明。

| 项目 | v3.0.0 | v3.1.0 | 验证证据 | 剩余差距 |
|---|---|---|---|---|
| 能力清单 | 模型、连接器、Skill 分散诊断 | 九类能力统一清单，未配置类别也显示 | `verify:external-capability-matrix`、诊断 UI 实测 | 真实账号尚未全部配置 |
| 状态表达 | 各模块状态名称不同 | 八态统一合同 | 单元测试与专项门禁 | 供应商特有错误仍需真实样本补充 |
| 可用判定 | 部分入口可能把配置或安装误当可用 | 只有真实调用且响应验收通过才可用 | 非真实事件覆盖保护测试 | 邮件/GitHub 写操作不能后台自动测试 |
| 恢复证据 | 各模块独立描述恢复 | 失败后真实复验成功才累计恢复次数 | 故障到恢复单元测试 | 真实限流恢复窗口待外部服务验证 |
| 凭据安全 | safeStorage 已用于连接器 | 矩阵只存脱敏状态和有限证据 | URL 凭据与查询密钥脱敏测试 | 仍需真实导出包人工复核 |
| 模型与图片 | 兼容矩阵保存在模型条目 | 兼容性真实测试同步进入总矩阵 | 模型兼容回归、图片路由回归 | 尚无多供应商真实账号报告 |
| 指定网页 | 原始 URL 合同已存在 | 读取成功/内容无效/失败进入统一状态 | 指定微信 URL 路由与网页读取门禁 | 动态站点仍受反爬和登录限制 |
| Skill 生命周期 | 安装、读取、调用证据不够直观 | 发现、规则、调用、产出、验收五段 | Skill v3 与三个聊天入口回归 | 需用真实复杂 Skill 做端到端人工验收 |
| 连接器与 MCP | 单连接器测试结果分散 | 测试和真实工具调用回写统一矩阵 | 连接器协议与 v2 核心门禁 | 知识库、邮件、GitHub、HTTP、MCP 真实账号待测 |
| 用户界面 | 诊断列表按模块展示 | 新增矩阵摘要、状态标签、恢复次数与脱敏详情 | 默认宽度与 780px 窄窗口实测 | 尚无时间筛选和单项历史详情页 |
| 人格协议 | v19 决策与模型韧性 | v20 增加外部能力真实验证协议 | Skill UI 人格门禁 | 后续大版本继续同步升级 |
| 发布门禁 | 发布脚本未包含阶段 A/B | 正式发布会执行阶段 A、B、阶段三与 v2 核心 | 安装包 `taiji-office-setup-3.1.0.exe` 已通过包内验收 | 本机覆盖和远端 Release 尚未执行 |

## 结论

阶段 B 的工程链路已经完成，能够诚实地区分“没配置”“没测过”“真的可用”和具体失败。当前不能称为真实环境验收完成，因为用户的图片、知识库、邮件、GitHub、HTTP 与 MCP 测试账号尚未全部接入。下一步应在客户端配置这些能力并逐项产生脱敏报告；未通过的项目留在矩阵中，不允许用模型判断替代。
