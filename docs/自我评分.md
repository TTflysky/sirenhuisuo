# 太极系统自我评分

> 评估基线：v2.6.1 本地源码与完整 v2 核心门禁
> 评估日期：2026-07-31
> 综合评分：**78 / 100**
> 阶段三目标：**88 / 100**，当前差距 **10 分**

## 结论

太极当前属于“功能完整度较高的高级 MVP / 预生产智能体平台”，已经不是只会聊天的界面，也不是依靠提示词假装执行的原型。它能够建立任务合同、调度真实员工、执行工具、保存证据、暂停恢复、创建 Coding 工作区并形成可回放记录。

但它还不能被评价为成熟商业级长期自治系统。最主要的原因不是功能少，而是标准测试体系、真实 Electron 长驻稳定性、跨版本更新回滚演练、核心模块拆分和外部生态兼容矩阵仍不完整。以个人研发项目衡量约 **86/100**；以交付给普通用户长期使用的商业软件衡量约 **72/100**；综合取 **78/100**。

## 已形成的优势

### 1. 任务已经脱离单轮聊天

- TaskRun、Turn Lifecycle、任务合同、恢复胶囊和持久账本共同保存目标、步骤、工具结果、用户插话与未完成事项。
- 暂停、继续、等待授权和失败是不同状态，不再全部压成一条聊天回复。
- 旧窗口快照不能删除活跃任务，解决了“界面还在但后台找不到任务”的关键一致性问题。

### 2. 团队是真实执行结构

- 268 名内置专家已经成为办公室员工，专业规则位于各自 `soul`，不是由助理临时扮演。
- ProjectBrief 可以编译为带依赖、责任能力、重试和验收条件的 DAG。
- 审查退回会定位责任步骤，已完成且无关的步骤不会全部重做。

### 3. Coding 能力已有独立基础设施

- 软件任务可以创建独立工作区或 Git Worktree，建立仓库文件/符号索引并查询依赖。
- 改动可保留 Diff、检查点、命令增量日志、测试证据和回滚信息。
- 产品、架构、UI/UX、前端、后端、测试与审查已经能够按职责形成项目链路。

### 4. “完成”越来越依赖证据

- 文件、连接、操作、回答和决策使用不同验收方式，模型口头声明不能直接越过完成门禁。
- Skill 的选择、规则读取、真实调用与最终验收被分开记录。
- 原生执行观测可以统计耗时、重试、失败分类、工具结果和证据完整度。

### 5. 错误更容易被定位

- 主进程、窗口、任务账本、恢复、IPC 和执行器写入统一脱敏诊断账本。
- 用户可从诊断中心导出错误记录，不再只能依赖截图和口述猜测。
- v2.6.1 增加模块边界和性能门禁，覆盖 268 名专家、320 员工、12000 条任务事件和 12 窗口广播。

### 6. 多模型和图片能力进入统一产品链路

- 模型库支持聊天模型和 GPT Image 2，助理、员工单聊和团队聊天均可切换。
- 无图片时执行文字生图；本轮上传图片时走真实图片编辑请求，源图不会只停留在气泡展示层。
- 图片能力复用统一模型配置，不是只为头像生成建立的专项通道。

### 7. 长期记忆开始具备质量控制

- 用户记忆支持规范化、相似去重、显式替换、正反冲突处理、重要度容量和分类复核周期。
- 待复核记忆不再注入模型；设置界面会显示修改原因并允许用户确认仍然有效。
- 当前事实仍高于旧记忆，避免历史偏好覆盖本轮明确要求。

## 仍然明显的劣势

### 1. 自主判断尚未达到稳定可信

任务语义内核已经比早期可靠，但还没有覆盖足够广的真实自然语言轨迹。含糊指代、跨轮纠错、多个并行目标和长期插话仍可能让模型选择错误目标或工具。当前验证证明了已收录场景，不代表所有表达方式都稳定。

### 2. 核心模块依然过大

- `nativeExecutionAdapter.cjs`：约 2157 行。
- `hermesClient.ts`：约 2227 行。
- `store.tsx`：约 2503 行。
- `theme.css`：约 3798 行。

v2.6.1 只完成了记忆、图片请求和部分原生策略拆分。Store 的状态、持久化和业务动作仍高度集中；Theme 也没有按办公室、聊天、任务和设置拆开。修改这些文件仍有较大的跨功能回归风险。

### 3. 测试数量多，但结构还不专业

当前核心代码约 153 个文件、46248 行，已有 91 个验证脚本，但标准 `test/spec` 文件仍为 0。很多门禁属于契约或源码结构检查，优点是覆盖业务历史问题，缺点是定位粒度、Mock 能力、组件交互测试和覆盖率统计都不如成熟测试框架。

### 4. 真实 Electron 稳定性证据不足

目前的 320 员工和多窗口性能测试是确定性内核基线，不是真实 Electron 连续运行压测。还没有形成 8-24 小时长任务、多窗口频繁开关、后台驻留、GPU 异常和内存泄漏的统一报告。真实 Electron UI 回归在当前机器环境仍不够稳定。

### 5. 更新和回滚没有完成真实跨版本演练

自动更新、下载校验、身份迁移、旧版本安装包准备和回滚代码已经存在，也有脚本测试；但还缺少从已发布旧版本发现新版本、下载、安装、迁移、故障注入、回滚并核对业务数据的完整实机记录。这一项未通过前，不能把“有回滚代码”等同于“升级失败一定可恢复”。

### 6. 外部生态兼容仍不够可预测

OpenAI 兼容接口、SkillHub、GitHub、ima 和普通 HTTP 服务的协议差异较大。当前已经解决多个具体链路，但还没有模型供应商、图片接口、Skill 格式、MCP/连接器和认证方式的正式兼容矩阵。第三方协议变化仍可能让用户首先感知为“太极不会用”。

### 7. 模型运行效率仍有改进空间

聊天主链路仍以非流式 Chat Completions 为主，前端主包约 5MB。长任务的首字反馈、并行工具调度、上下文裁剪成本和失败后模型调用预算还没有达到成熟 Agent 平台水平。

### 8. 企业级凭据与治理能力不足

当前有脱敏、权限和用户审批，但还不是 Vault/KMS、短期凭据、组织策略、细粒度审计保留和多租户隔离体系。作为本地个人客户端可以接受，作为企业级平台仍不够。

## 当前定位

太极现在可以作为高强度内部测试版本，适合继续用真实任务挖掘内核问题；还不适合宣称为无需监督的成熟商业自治平台。下一阶段不应继续堆大量表面功能，而应把剩余 10 分集中投入测试标准化、模块拆分、真实长驻性能和更新回滚证据。
