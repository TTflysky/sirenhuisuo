# 太极 v3.2 阶段 C 差异矩阵

评估日期：2026-08-01
基线：v3.1.0
目标：让长任务、多人团队和多窗口客户端在规模增长后仍可观察、可恢复、可维护。

| 项目 | v3.1.0 | v3.2.0 | 验证证据 | 剩余差距 |
|---|---|---|---|---|
| 核心模块边界 | 客户端、Store、原生执行器仍偏大 | 本地状态持久化、员工运行状态投影、原生任务公开投影分别抽出 | `verify:module-boundaries` | 三个核心模块仍超过 2100 行，阶段 D/E 继续按职责拆分 |
| 主渲染包 | 单 JS 约 5.14 MB | 主包约 0.81 MB，专家目录、React、Ant Design 独立分包 | `verify:renderer-bundles`，主包下降 84.1% | 专家目录仍有约 3.48 MB，多个窗口会各自持有员工运行数据 |
| 构建告警 | 5 条无效动态导入与大包告警 | 静态依赖与延迟桥接边界一致，生产构建无上述告警 | `npm run build` | 字体资产仍大，但由浏览器按资源加载且不属于 JS 解析路径 |
| 项目看板 | 阶段、负责人、进度和结果 | 增加阶段/步骤耗时、证据总数与验证数、等待条件、下一步和责任返工范围 | `verify:project-board` | 尚未做超长项目的虚拟滚动 |
| 恢复语义 | 根任务聚合子任务，定向返工已存在 | 看板明确显示“仅返工”责任步骤，重试/子任务继续归入同一项目 | 项目看板专项断言 | 真实三类大型项目留到阶段 E 验收 |
| 320+ 员工 | 有目录投影性能基线 | 320 员工 500 次投影约 5-7 ms | `verify:phase3-performance` | 12 窗口总渲染堆约 645 MB，稳定但仍偏重 |
| 长任务与高频事件 | 12000 事件基础测试 | 40 项目、3200 步骤、100 次看板投影约 0.44 秒；事件堆增量约 2.2 MB | `verify:phase3-performance` | 仍需真实数小时任务与真实模型输出负载 |
| 多窗口短驻留 | 已有脚本但启动存在竞态 | 等待 preload 桥接就绪；真实桌面权限下 12 窗口全部打开，短驻留堆增长 0.15 MB | `verify:phase2-soak:smoke` | 正式 8 小时驻留未执行，不能用短冒烟代替 |

| 人格协议 | v20 外部能力真实验证 | v21 增加长任务状态、增量投影、阶段看板和长期测试诚实边界 | `verify:phase-c-persona` | 后续大版本继续同步升级 |

## 结论

阶段 C 的代码、确定性性能门禁、无警告构建、12 窗口短驻留和 Windows 安装包验收已经完成。安装包为 `release/taiji-office-setup-3.2.0.exe`，大小 `195846389` 字节，SHA-256 `32266E279020CB74F6284D7A8F37853C56D3B3CFA95EDB88A06E17F0BE0A4BE0`。正式 8 小时驻留尚未实际执行，因此“8 小时无持续内存增长、无任务丢失”仍是未验收项，不能写成通过。v3.2.0 可以作为阶段客户端供用户做真实使用测试，但长期稳定性结论仍需补正式驻留报告。
