> 制定日期：2026-07-31
> 当前基线：v2.6.2，综合评分 79/100
> 阶段目标：v2.7 达到 82 分，v2.8 达到 86 分，v2.9 达到 88 分，v3.0 完成正式候选验收
> 执行原则：先修内核和证据链，再扩展表面功能；小版本本地验证，阶段版本验收后统一打包发布

> 执行状态（2026-08-01）：**第一阶段 v2.7.4、第二阶段 v2.8.4 已发布；第三阶段 v2.9.0-v2.9.4 已完成代码收口与专项门禁**。模型/图片兼容矩阵、Skill Runtime、safeStorage 凭据、更新事务、SBOM/来源证明和人格 v18 已落地。正式 8 小时长驻、真实第三方账号矩阵、真实跨版本回滚和远端安装资产哈希仍是 v3.0 候选验收项，不在结构化测试中冒充通过。

## 1. 当前定位

太极已经具备任务合同、员工与团队调度、工具执行、持久任务、暂停恢复、Coding 工作区、证据验收和诊断导出，但仍属于高级 MVP / 预生产平台。第二阶段已经补齐 ExecutionController v2、Coding Runtime v2 与真实 Electron E2E；进入第三阶段后，最主要的差距不是“功能按钮不够”，而是以下能力仍需形成可重复、可量化的工程保证：

1. 自然语言目标、当前对象和旧上下文之间仍可能发生混淆。
2. ExecutionController 已能分类失败、禁止无效重复并保存检查点，但仍需扩大真实外部服务的失败样本矩阵。
3. 标准测试和真实 Electron E2E 已建立；12 窗口短驻留已通过，正式 8 小时长驻与更多异常恢复证据仍待专项验收。
4. Skill、连接器、网页、模型和图片服务缺少正式兼容矩阵。
5. 自动更新、迁移和失败回滚尚未完成完整实机演练。
6. 核心模块仍然过大，修改局部功能容易触发跨模块回归。

## 2. 已知未解决问题

### KNOWN-URL-001：指定链接正文无法稳定读取

**复现输入**

```text
https://mp.weixin.qq.com/s/6d_2gn2jK3lVTJaeookHkA
总结链接内容。
```

**v2.6.2 实际结果**

- 精确网页读取多次失败。
- 执行过程继续尝试了网络搜索、终端脚本、下载文件和工作区检查。
- 最终因没有取得指定地址的正文证据而停止，没有再拿无关搜索结果冒充总结。

**当前判断**

v2.6.2 的明确资源合同只解决了“不得替换用户给出的 URL”和“无原文证据不得宣称完成”，没有解决“如何可靠取得受反爬、登录态、动态渲染或网络策略影响的正文”。因此该问题仍然存在，不能标记为已修复。

**完成版本**：v2.7.4。`KNOWN-URL-001` 已由浏览器会话取得 1219 字正文，且未执行无关搜索。

**计划中的根治方向**

- 将资源身份、资源获取、内容解析、证据验收拆成四层，不再混在模型工具选择里。
- 直接 HTTP 失败后，根据真实错误在浏览器登录态读取、官方接口、用户附件/正文之间选择不同路线。
- 指定 URL 任务禁止退化为主题搜索；搜索只能用于发现资源，不能替代已指定资源。
- 每次失败记录获取器、状态码、页面类型、正文长度和失败类别，ExecutionController 只能选择与失败类别不同的下一路线。
- 没有正文时明确报告“地址已确认，但正文未取得”，不运行与目标无关的终端或工作区检查。

本计划只记录该问题，本轮不修改实现。

## 7. v3.0.0 正式候选验收

v3.0.0 不再堆叠新功能，只做冻结、修复和全链路验收。

### 必须通过的场景

1. 普通问答、文件处理、指定网页总结、资料搜索和图片生成/编辑。
2. 指定 Skill 安装、模糊 Skill 搜索、显式调用、员工调用和团队调用。
3. 单员工任务、临时团队、长期团队、点名员工、动态补人和责任返工。
4. 真实软件项目从需求、方案、UI、编码、测试、审查到交付。
5. 暂停、继续、授权、取消、客户端重启、窗口关闭和异常恢复。
6. 8 小时长驻、大员工列表、多窗口和后台驻留。
7. 从旧正式版自动更新到 v3.0.0，并完成一次故障回滚演练。
8. 诊断包可以定位每次失败的任务、步骤、工具、错误类别和最后证据。

### 发布判定

- 所有 P0/P1 缺陷关闭，P2 缺陷有明确限制和绕行方式。
- 核心测试、集成测试、Electron E2E、性能和升级回滚报告齐全。
- 安装包、源码、文档、人格和 GitHub Release 完全一致。
- 用户数据迁移通过数量核对与内容抽样。
- 自我评分达到 88 分以上，但不宣传为“无需监督的完全自治系统”。

## 8. 每个版本的固定交付清单

1. 功能代码与数据库/本地数据迁移。
2. 新增单元、集成、E2E 或故障注入测试。
3. 内置人格升级或确认本版无需升级；阶段大版本必须升级人格。
4. CHANGELOG、README、交接文档、差异矩阵和自我评分。
5. 真实失败样例加入回归库，不只记录成功路径。
6. 小版本仅本地验证；阶段验收版本才打包客户端并发布 GitHub。
7. 发布前核对用户配置、员工、团队、会话、任务、记忆和工作区未丢失。

## 9. 执行优先级

| 优先级 | 项目 | 原因 |
|---|---|---|
| P0 | 标准测试体系、Store 拆分、通用资源获取、ExecutionController v2 | 直接决定后续修改是否可靠，以及智能体是否会重复走错路线。 |
| P1 | Coding Runtime、团队协作、Electron E2E、长驻性能、更新回滚 | 决定太极能否真正长期完成项目。 |
| P2 | 外部生态矩阵、凭据治理、发布签名和 SBOM | 决定对外发布后的兼容性、安全性和维护成本。 |
