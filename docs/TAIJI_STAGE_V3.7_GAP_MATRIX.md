# 太极 v3.7.0 动态计划差异矩阵

更新时间：2026-08-04

| 能力 | v3.6.1 状态 | v3.7.0 状态 | 与成熟 Agent/Hermes 的剩余差距 |
| --- | --- | --- | --- |
| 长期目标身份 | 有统一 `GoalState`，执行仍以固定计划为主 | 目标与可修订计划图绑定并可重启恢复 | 跨设备、跨会话长期任务仍需更强的远程 Worker 与租约治理 |
| 动态计划 | 只能记录影子建议 | 同一计划支持增删改、依赖调整、局部重开和废弃 | 还缺模型主动生成高质量替代方案的系统化评估器 |
| 失败恢复 | 固定重试与暂停 | 失败分类、两轮换路、保留成果、到边界停止 | 尚未建立跨 Connector 的通用补偿事务库 |
| 团队人员调整 | UI 名单可变化，计划事实不完整 | 补人、换人、原因、影响节点和新增验收进入计划历史 | 自动能力缺口发现和主动招聘仍需要 v3.8 主持层 |
| 审查返工 | 可退回，但计划版本表达不足 | 只重开责任节点和受影响下游 | 复杂多审查人仲裁、分支合并策略仍不完整 |
| 模型工具入口 | 模型无法正式提交计划修订 | 新增计划修订和节点改派工具 | 需要进一步约束低质量或无证据的模型修订提案 |
| 预算 | 轮次/步数边界较固定 | 风险、进展、上下文与硬上限组合判断 | 成本预测仍未按模型、任务价值和外部调用价格动态计算 |
| 可观察性 | 能看任务、工具和公开判断 | 增加计划版本、影响节点、保留完成项和最近修订 | 仍缺完整计划版本 Diff 和图形化依赖视图 |
| 工程边界 | 核心模块接近行数上限 | 恢复控制与成员同步已抽离 | `hermesClient`、`store`、Adapter 仍偏大，需要持续按职责拆分 |
| 真实交付 | 已验证单一科学计算器任务 | 待本版安装后真实项目跟跑补齐 | 一个样本不能代表长期、多外部系统和跨重启稳定性 |

## 本版结论

`v3.7.0` 解决的是“计划是否真的能变、失败是否真的会换路”的内核问题，不是增加某个任务关键词通道。太极已从记录建议的影子控制层进入可执行的自适应计划阶段，但还没有达到 Hermes 类成熟 Agent 的长期远程执行、通用补偿和自主团队主持水平。
