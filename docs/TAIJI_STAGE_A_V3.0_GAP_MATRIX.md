# 太极 v3.0 阶段 A 差异矩阵

评估日期：2026-08-01
基线：v2.9.5
目标：把语义理解和模型暂时不可用从“感觉”变成可回归、可审计、可恢复的系统能力。

| 项目 | v2.9.5 | v3.0.0 | 验证证据 | 剩余差距 |
|---|---|---|---|---|
| 语义轨迹规模 | 200 条，195 条通过 | 400 条，400 条通过，门槛 98% | `verify:task-semantics-benchmark` | 仍需持续加入真实失败语料，尤其长上下文与多语言 |
| 决策过程 | 规则回退与模型候选一次归一化 | 候选理解、上下文、治理、计划四层审计 | `verify:task-decision-pipeline` | 尚无专门审计浏览器，当前随合同持久化 |
| 控制语义 | “停止执行”部分词序漏判 | 停止/暂停/继续控制覆盖扩展 | 400 条基准与单元测试 | 自由口语和方言仍需真实样本 |
| 团队路由 | 泛化命令规则可能提前截获 | 明确团队目标优先进入团队调度 | 团队扩展轨迹 10 条 | 复杂混合目标仍依赖模型做主判断 |
| 模型健康 | 单次兼容性测试 | 运行期请求、成功、失败、耗时和状态累计 | `modelReliability` 单元/集成测试 | 未接组织级集中指标系统 |
| 熔断与恢复 | 每次请求独立失败 | 三次瞬时失败打开、冷却后半开探测、成功关闭 | 503 故障注入 | 阈值暂为本机统一默认，尚无按供应商配置 |
| 退避 | 由上层重试策略间接控制 | 按失败类别确定性指数退避 | `verify:model-reliability` | 尚未加入服务商 `Retry-After` 解析 |
| 供应商切换 | 用户手动自行判断 | 根据已配置聊天模型给出备用建议 | 恢复建议测试 | 不静默自动切换；跨供应商业务一致性留待真实矩阵 |
| 故障分类 | 503 已归类，运行统计不足 | 503、429、超时、网络分别入账 | 4 类聊天调用注入测试 | 鉴权、计费、内容过滤和协议漂移留待阶段 B 真实矩阵 |
| 首 token 与总耗时 | Token 记账，无统一首 token 健康指标 | 流式首 token、总耗时和平均值持久化 | 模型可靠性测试 | 非流式接口无法得到真实首 token，不做伪估算 |
| 用户可见性 | 连接测试与故障文案 | 诊断中心显示运行期成功率、耗时、失败分布、保护状态和恢复次数 | 生产构建 | 尚无时间范围筛选和导出专用模型指标 CSV |
| 模块边界 | `hermesClient.ts` 接近边界 | 上下文整理与模型请求生命周期独立拆分，核心客户端 2294 行 | `verify:module-boundaries`、标准测试 `49/49` | 后续仍需继续拆分传输与执行编排 |
| 人格协议 | v18 外部生态与发布边界 | v19 加入四层决策与模型韧性协议 | `verify:image-model-routing` | 后续每个大版本继续同步人格 |

## 结论

阶段 A 的代码目标和确定性验收已完成。它降低了“误解后沿错路执行”和“供应商故障时重复消耗”的概率，但不等于真实外部生态已经可靠。阶段 B 必须用真实账号和真实服务完成模型、图片、Skill、网页、MCP、知识库、邮件、GitHub 和 HTTP 的成功与失败矩阵。
