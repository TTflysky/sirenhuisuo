# 太极 v2.0 统一智能体运行时

## 目标

v2.0 不重写太极，也不复制 Hermes 的品牌、CLI 或 Python 工程。它保留现有 Electron UI、TaskService、Worker、员工与团队、聊天、人格、长期记忆、Skill、Connector、审批和本地数据，只统一这些入口背后的行动闭环。

```text
模型理解目标
-> 模型选择动作和精确参数
-> 运行时校验工具、Schema、安全、权限、审批和预算
-> 原样执行工具参数
-> 真实结果回注模型
-> 模型重新判断
-> 按交付类型验收
-> 统一收尾或可恢复交接
```

## 责任边界

| 决策 | 负责人 |
| --- | --- |
| 用户当前真正要完成什么 | 模型任务决策 |
| 下一步使用什么能力、工具和精确参数 | 行动模型 |
| 工具是否存在、参数是否符合 Schema | Tool Registry 与 Turn Runtime |
| 是否越权、需要审批或触及安全边界 | 安全与审批运行时 |
| 是否重复消耗、是否超出上下文或工具预算 | ExecutionController 与 Context Router |
| 员工是否真实存在、在线且覆盖声明能力 | Capability Graph |
| 工具产生了什么真实结果 | 原生工具运行时与证据账本 |
| 结果是否满足回答、文件、连接、操作或决策交付 | 任务合同、真实证据与模型复核 |

确定性运行时不得用关键词替模型重写搜索词、文件目标、连接器参数或业务路线。明确的 Skill 包来源是一个安全例外：模型决定安装后，运行时必须使用原生原子安装器，不能临时拼接 Shell 安装命令。

## 核心模块

### Turn Runtime

`src/engine/turnRuntime.mjs` 保存每轮可审计状态：当前目标、交付类型、模型决定、工具参数、工具结果、结果引用、未决问题、恢复次数、用户最新插话和最终收尾。它不记录隐藏思维链。

助理与员工聊天通过 `src/data/hermesClient.ts` 接入，原生团队 Worker 通过 `electron/nativeExecutionAdapter.cjs` 接入。两个入口使用同一错误分类、参数规范、恢复动作和 Finalizer。

### Capability Graph

`src/engine/capabilityGraph.mjs` 使用稳定能力 ID 做最小覆盖组队。UI/UX 设计不自动等同前端代码实现；前端、后端、调研、办公文档、Connector、Skill、工程、审查和协调彼此独立。用户明确点名的成员优先，确定性选择只在真实员工目录中补齐缺失能力。

### MoA Runtime

`src/engine/moaRuntime.mjs` 为高风险、审查或多能力步骤提供私有顾问建议。顾问没有工具、不能改变任务状态、不能面对用户宣布完成。行动员工保留工具、停止权和最终责任，避免多人都以为别人已经完成。

### Typed Delivery

任务交付分为 `answer`、`file`、`connection`、`operation`、`decision` 和 `mixed`。只有 `file` 强制真实文件证据；连接任务要求真实测试证据，操作任务要求真实运行结果，普通问答允许直接形成清晰答案。

团队聊天编译出的交付类型、验收标准、约束、能力和风险等级会进入 TaskRun 合同，不再在创建任务时丢失并被规则重新猜测。

## 失败与恢复

错误被分类为认证、授权、计费、限流、超时、网络、服务端、上下文溢出、参数错误、缺少依赖、结果偏题、验收失败、缺少用户条件或未知错误。

- 认证、授权、计费和用户必须提供的条件进入 `waiting_user`，保存现有进度并说明唯一缺项。
- 瞬时错误只做有限重试，随后换路线。
- 参数错误回到模型修复 Schema。
- 缺少能力先发现工具或依赖，仍无法取得才请求用户。
- 上下文接近上限先压缩目标、参数、结果、引用与未决问题；多次压缩仍不足则形成 checkpoint。
- 完全相同的工具参数和结果不能无限重复。

## 用户插话

运行中插话首先进入观察阶段。暂停、停止、继续、纠错、问题、约束和独立新任务有明确控制语义；模型收到当前目标、已完成证据和最新插话后再决定继续、修订、暂停或排队。关闭聊天窗口不等同于暂停后台任务。

## 数据兼容

v2.0 没有重命名或清空现有 localStorage 键、用户目录、TaskService 账本、员工、团队、聊天、模型、人格、记忆、Skill 或 Connector 数据。覆盖安装继续沿用旧数据，新增状态均为可选字段并有恢复默认值。

## 发布门禁

```powershell
npm.cmd run verify:v2-core-gate
npm.cmd run verify:v1-core-gate
npm.cmd run dist:win
npm.cmd run verify:package
```

`verify:v2-core-gate` 包含统一运行时轨迹、跨模块智能体轨迹、原生执行、能力调度、动态委派、上下文工具对、上下文路由、任务合同、Runner、执行证据和工具注册中心。`verify:v1-core-gate` 保留旧功能与故障注入回归，防止大版本破坏已有基础设施。
