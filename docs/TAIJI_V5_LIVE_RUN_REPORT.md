# 太极 V5 真实陪跑报告

最后整理：2026-08-06

## 结论

V5 的静态门禁、构建和基础实体隔离已经完成，但本次真实客户端陪跑没有通过“自主智能体团队”验收。问题不是科学计算器或风险看板这两个项目本身，也不是继续增加提示词就能解决；它们暴露的是所有项目都会遇到的运行时断点。

在模型工具输出适配和普通助理入口接入统一任务内核之前，不能把 V5 宣称为真实自主完成版。本报告因此同时记录已交付能力、真实失败证据和下一轮通用修复门禁。

## 根因与通用修复

### P0-1：模型工具调用适配层不完整

模型协议和渲染/执行层之间缺少唯一网关。DeepSeek DSML 被当作普通文本，而原生 OpenAI `tool_calls` 与其他结构化回退没有经过同一验证路径。

修复要求：

1. 在任何窗口渲染或工具执行前建立唯一 `ModelOutputGateway`。
2. 统一支持原生 `tool_calls`、DeepSeek DSML `tool_calls` 块和严格的结构化 JSON 回退。
3. 解析后只允许工具注册表中的名称，参数按工具 schema 校验并写入原始响应、解析结果和拒绝原因。
4. 控制标记不得进入用户可见消息；未知、畸形或参数不完整的调用必须产生诊断事件并触发有限重试/换路，不能伪装成普通回答或完成。
5. 流式和非流式、助理/员工/团队/Worker/后台五类入口必须复用同一适配器，避免再次出现“某个窗口能用、另一个窗口不能用”。

### P0-2：普通助理直写路径绕过项目内核

普通助理仍可能直接走文件写入路径，没有强制建立项目、任务、工作区和产物关系，导致“口头说完成但没有可定位文件”。

修复要求：

1. 每个可执行回合先创建或恢复 `conversationId`、`projectId`、`taskId`、`workspaceId`，并载入当前 GoalFrame；长期记忆可共享，但任务和审批默认不能跨项目继承。
2. 所有读取、搜索、写入、运行、验证动作只能由 `TaskService`/`ProjectContext` 生成和执行，禁止任何窗口组件或快捷路径绕过登记。
3. 写入成功不等于完成。收尾至少需要：文件存在、路径位于当前工作区、产物已登记、运行/验证证据已保存、最终门禁记录 accepted 或明确 blocked。
4. 项目文档、事件账本和产物分类必须在同一项目目录下长期可追溯；模型声明不能关闭任务。
5. 失败时保留目标、假设、已尝试路线和证据，先归因再换工具/换路线；禁止无限重复同一动作，也不能为某个项目添加关键词分支。

## 下一轮验收顺序

1. 用协议夹具覆盖三种模型输出格式，并确认控制标记不出现在聊天文本。
2. 重新运行科学计算器：必须看到项目文档、独立工作区、实际 HTML、产物登记和桌面/移动运行验证。
3. 重新运行风险看板团队：必须看到结构化团队提案、成员计划回合、真实工具调用、阶段证据和最终报告。
4. 重启客户端后重新打开两个项目，确认项目文档、任务账本、产物和未决问题可以恢复，且新聊天不会污染旧项目。
5. 通过后再将 V5 标记为真实自主智能体团队可验收；在此之前只能称为“V5 内核基础设施已交付，真实运行仍有 P0 缺口”。

## 产品边界

这些修复服务于太极的终极目标：让模型根据目标、证据、阻塞和用户插话自主决定下一步，由确定性内核守住安全、权限、事实、证据和恢复边界。状态机、任务图和审批是护栏，不是替用户预先写死的工作流。不能用更长提示词、固定人员名单或针对某个项目的特殊判断冒充自主性。
