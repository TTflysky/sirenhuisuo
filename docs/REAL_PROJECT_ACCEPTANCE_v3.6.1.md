## 通用内核修复

1. `run_command` 的 `cmd` 与 `command` 归一为同一路线，不同命令保留不同路线键。
2. 成功 `write_file` 后只把路径和内容长度摘要回注模型；失败写入仍保留原参数用于纠错。
3. 聊天任务保存真实 `workspaceId`、artifact、tool attempt、turn runtime 和 execution state。
4. 心跳在 250ms 内合并；大于 2MB 的任务账本采用 500ms 合并检查点，事件仍立即追加以支持崩溃恢复。
5. 前台最多等待账本收尾 1.5 秒，回答可先显示，账本继续安全落盘。
6. 网页、浏览器、视口、截图和窄屏验收查询可以发现本地命令执行能力。
7. Web UI 验收同时检查桌面与不宽于 390px 的窄屏，不保存或展示隐藏思维链，只记录公开动作与工具证据。

## 用户复核发现的验收盲区

Electron 测试视口报告 `innerWidth=375`，但垂直滚动条占位后 `documentElement.clientWidth=360`。旧脚本仍把 375 当右边界，所以没有发现卡片与 5px 外阴影已经进入滚动条区域。

新规则使用 `min(documentElement.clientWidth, visualViewport.width)` 作为真实可用宽度，并额外检查：

- 可见元素是否越过真实边界；
- 是否被父容器裁切；
- 粗边框和外阴影是否完整可见；
- 主要带框容器是否保留至少 8px 安全间距；
- 验收脚本是否锁定任务产物的绝对路径，防止多个旧页面串版。

按新规则，第二轮产物被正确判为“功能通过、窄屏视觉未通过”。
