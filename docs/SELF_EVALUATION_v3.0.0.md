## 本阶段优势

1. **模型判断与运行时约束分开。** 模型负责理解和规划，运行时只固定对象、权限、状态和证据；没有为每个问题新写一条产品通道。
2. **决策可复盘。** 四层审计记录输入摘要、接受结果和拒绝原因，并随任务合同保存，不依赖下一次模型重新解释。
3. **供应商故障有状态。** 瞬时故障会积累健康状态，达到阈值后停止重复请求，冷却后只做一次探测。
4. **恢复由用户控制。** 系统可以建议备用模型，但不会在未授权时静默改变模型。
5. **指标来自真实调用节点。** 总耗时、流式首 token、状态码、失败类别和恢复结果在请求链路上记录；非流式首 token 不伪造。
6. **功能增长没有突破旧模块边界。** 聊天上下文和模型请求生命周期被拆为独立模块，核心客户端保持在 2300 行门禁以内。

## 仍然不足

1. **400 条仍是确定性基准。** 它证明已知类别没有回退，不代表所有自然语言、方言、超长上下文和跨语言输入都能达到 98%。
2. **真实供应商矩阵缺失。** 当前 503、429、超时和网络为自动化注入，不等于 OpenAI、DeepSeek、Qwen 等真实供应商都已完成故障恢复验证。
3. **熔断策略仍是本机统一默认。** 尚未解析 `Retry-After`，也没有按供应商配置阈值、冷却窗口和 SLA。
4. **模型指标只保存在本机。** 诊断中心可见，但没有按时间筛选、集中采集、跨设备聚合或组织级告警。
5. **核心模块仍大。** `hermesClient.ts` 继续承担请求编排；本阶段新增逻辑已拆模块，但后续仍需切分传输、遥测和执行职责。
6. **正式稳定性和发布证据未补。** 8 小时驻留、跨版本故障回滚、Windows 签名和 GitHub 下载后哈希仍未完成。
