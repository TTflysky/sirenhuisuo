# 太极自主智能体架构升级说明

> 状态：产品方向基线，2026-08-03 确认
> 当前基线：`v3.6.0`（自主控制内核已以影子模式接入）
> 目标版本：`v4.0.0`
> 优先级：最高。后续调度、执行、记忆、团队和界面改造不得与本文冲突。

## 1. 为什么需要这次方向纠偏

太极的目标不是“由智能体驱动的固定工作流”，而是能够理解长期目标、观察现场、主动找路、使用工具、验证结果、修正错误并组织团队完成交付的自主智能体平台。

当前系统已经拥有工作区、任务账本、工具、权限、证据、审查、恢复、团队和长期记忆等重要基础，但为了抑制乱调度、虚构完成、重复调用和无限循环，控制权逐渐转移到了固定角色基线、固定 Coding DAG、步骤类型和工具预算。结果是系统更稳定，却容易表现为机械执行预设流程。

本次升级不推翻现有项目。正确做法是保留可靠执行底座，新增目标驱动的认知控制层，并把固定工作流降级为智能体可以创建、修改和废弃的执行载体。

## 2. 产品北极星

太极的统一定义：

> 目标是核心，模型负责判断，工具负责行动，计划负责承载，证据负责验收，记忆负责进化，权限负责边界。

用户给出一个目标后，太极必须能够：

1. 保持原始目标和成功条件，不因最近一句话丢失项目身份。
2. 根据真实现场决定下一步，而不是机械执行首次生成的步骤。
3. 主动读取资料、寻找工具、检查环境和尝试替代路线。
4. 发现方向错误、证据不足或路线无效时自行纠错和重规划。
5. 只有在密码、验证码、付费、删除、对外发送、关键歧义或能力确实缺失时请求用户参与。
6. 用真实文件、工具结果、运行验证和审查证据证明完成。
7. 在暂停、重启、换窗口和用户插话后恢复同一个目标与现场。

## 3. 不可破坏的架构原则

### 3.1 工作流不是大脑

- DAG、步骤模板和角色基线只能提供初始建议、依赖约束和安全兜底。
- 模型可以基于新证据调整顺序、拆分或合并步骤、补人、换人、切换工具、建立实验路线或废弃无效步骤。
- 内核校验事实、权限、资源范围和完成证据，但不得把模型重新限制为填固定流程表格。

### 3.2 目标状态是最高事实源

- 每个项目必须有稳定的 `goalId`、`projectId` 和 `conversationId`。
- 原始目标、当前目标、成功条件、用户约束、禁止事项和范围变更必须结构化持久化。
- “继续”“换一个 UI 设计师”“增加图生图”“刚才那条不对”只能更新或控制当前目标，不能从最近聊天重新创建项目。

### 3.3 模型做语义判断，确定性内核守边界

- 模型负责理解意图、提出假设、选择路线、决定是否重规划和组织人员。
- 确定性规则只负责身份、权限、路径、预算、重复调用、证据和危险操作检查。
- 规则不得根据几个关键词直接决定完整团队、完整计划或最终答案。

### 3.4 计划必须可变

- 计划是当前认知下的执行假设，不是不可修改的合同。
- 每次获得重要结果、失败、用户纠正或审查退回后，都必须允许重新评估计划。
- 已完成且证据有效的步骤应保留；重规划只修改受影响部分。

### 3.5 自主不等于无限制

- 自主性发生在权限、沙盒、工作区和用户授权范围内。
- 密码、验证码、付费、删除、对外发送、账号权限和不可逆操作必须停下来确认。
- API Key 和私密内容不得进入模型长期记忆、日志、GitHub 或安装资源。

### 3.6 不展示隐藏思维链

界面展示可审计的公开决策摘要，不保存或展示模型隐藏思维过程。公开摘要必须包含：

- 当前目标
- 已确认事实
- 当前缺口或阻塞
- 已尝试路线及结果
- 下一步动作与原因
- 使用的员工、工具和资源
- 完成证据或需要用户处理的事项

## 4. 目标架构

### 4.1 Goal State

`GoalState` 是项目长期身份与目标合同，至少包含：

```text
goalId
projectId
conversationId
originalGoal
currentGoal
successCriteria[]
constraints[]
prohibitions[]
scopeChanges[]
userDecisions[]
status
```

它不能从聊天窗口临时重建。聊天只是输入，`GoalState` 才是执行事实源。

### 4.2 Situation Model

`SituationModel` 表示智能体当前掌握的真实现场：

```text
confirmedFacts[]
assumptions[]
openQuestions[]
availableCapabilities[]
activeMembers[]
artifacts[]
evidence[]
failures[]
blockedBy[]
userSteering[]
```

所有事实必须带来源和时间。模型推测只能进入 `assumptions`，不得伪装成事实。

### 4.3 Decision Engine

决策引擎每轮根据目标和现场生成有限的公开行动决定：

```text
observe -> interpret -> propose -> validate -> act -> verify -> reflect
```

每个 `DecisionRecord` 至少记录：

```text
decisionId
goalId
observedFacts[]
selectedAction
publicRationale
expectedEvidence[]
riskLevel
approvalRequirement
result
nextDecision
```

`publicRationale` 是简洁理由，不是隐藏思维链。

### 4.4 Adaptive Plan Graph

当前固定 Coding DAG 改为可修订计划图：

- 初始模板可提供产品、架构、设计、实现、验证和交付等建议阶段。
- 计划节点有目标、负责人、依赖、输入、期望产出、验收条件和状态。
- 节点可以增删、拆分、合并、替换负责人或修改依赖。
- 每次修改保留 `revision`、触发原因和影响范围。
- 审查失败只重开责任节点和受影响下游，不清空全部项目。

### 4.5 Reflection and Recovery

失败后的默认行为不是重试，而是先分类：

- 临时服务故障
- 配置或凭据缺失
- 工具不可用
- 参数错误
- 目标理解错误
- 证据不足
- 路线无效
- 权限边界
- 外部条件等待

相同路线最多重复两次。继续前必须产生新证据、新参数、新工具或新策略。否则应切换路线、重规划、请求能力或向用户说明明确阻塞。

### 4.6 Team Supervisor

助理或策划者是团队主持人，不是固定步骤播报器：

- 根据目标和当前阶段选择成员。
- 确认岗位覆盖，但不把岗位模板当作最终名单。
- 只启动依赖已经满足的员工。
- 接收员工交接、验证产出并决定下一负责人。
- 发现能力缺口时主动补人或请求安装 Skill/连接器。
- 用户插话时立即确认收到，再判断是询问、纠正、补充约束、控制命令还是新目标。
- 重大方向改变时暂停受影响节点，不干扰无关已完成工作。

员工拥有局部目标、独立工作区、工具现场、恢复点和阶段记忆，但不能自行改写项目总目标。

## 5. 现有模块的职责调整

| 现有模块 | 保留能力 | 必须停止承担的职责 |
| --- | --- | --- |
| `taskDecisionKernel` | 轮次关系和语义候选 | 单独决定完整执行路线 |
| `capabilityGraph` | 能力事实、岗位缺口和候选集 | 根据关键词锁死最终团队 |
| `codingProject` | 初始项目模板和依赖建议 | 生成不可修改的固定 DAG |
| `teamMembership` | 成员身份、能力和名单变更 | 从最近一句话重新匹配项目 |
| `nativeExecutionAdapter` | 执行已批准行动和收集证据 | 主持长期目标与反复自行规划 |
| `turnRuntime` | 单轮工具生命周期、预算和中断 | 用轮次数代替目标进展判断 |
| `TaskService/账本` | 事件事实源、恢复和审计 | 接受模型自述覆盖真实证据 |
| 审查与完成门禁 | 校验产出和责任返工 | 规定所有项目必须走同一流程 |

## 6. 版本路线

### v3.6.0：自主控制内核

目标：建立新的大脑层，但先以影子模式接入，避免直接破坏现有执行。

- 新增 `GoalState`、`SituationModel`、`DecisionRecord` 和持久化事件。
- 从聊天、团队项目和原生任务统一建立目标身份。
- 新增决策循环和公开决策摘要。
- 当前执行器继续工作，新控制层并行记录“它会如何决策”，用于对比固定流程。
- 建立目标保持、用户纠正、暂停恢复和事实/假设分离测试。

完成条件：新旧执行对照中，目标身份稳定，重启可恢复，用户插话不丢失，影子决策不产生副作用。

### v3.7.0：动态计划与自主恢复

实现状态：已在 `v3.7.0` 落地。当前自主控制模式由 `shadow` 切换为 `adaptive`，计划修订、失败换路和人员变更进入同一任务账本；危险动作仍受原有审批与权限边界约束。

- 将 Coding DAG 迁移为 `AdaptivePlanGraph`。
- 加入路线历史、重复检测、失败分类、能力发现和替代路线选择。
- 支持局部重规划、补人、换人、重新分配和责任范围返工。
- 工具预算从固定停止值改为风险、进展和上下文预算组合判断，仍保留硬安全上限。

完成条件：同一路线不机械循环；计划可以根据真实失败局部修改；已完成证据不丢失。

### v3.8.0：自主团队主持

- 助理/策划者使用目标状态和现场模型主持团队。
- 员工交接变为结构化输入、产出、证据、风险和下一建议。
- 支持有限并行，仅允许没有依赖冲突的节点并行。
- 项目看板展示当前目标、正在工作的员工、等待条件、下一负责人和公开决策摘要。

完成条件：团队不是按名单机械串行，也不是所有人同时开工；主持者可以根据阶段主动调整人员与顺序。

### v3.9.0：经验学习与个体适配

- 建立情景记忆、语义记忆、程序记忆和用户偏好四类边界。
- 只从已验证结果提炼可复用经验，失败经验记录适用条件。
- 新任务可检索相似项目，但旧项目不得覆盖用户当前明确要求。
- 学习结果可查看、修改、禁用和删除。

完成条件：相似任务减少重复探索，同时不会因旧记忆答非所问或继承错误目标。

### v4.0.0：自主智能体正式验收

- 移除由固定工作流主导的默认路径，新的自主控制层成为唯一主持入口。
- 保留旧任务数据迁移和恢复适配，不损坏员工、团队、聊天、模型、Skill 和工作区。
- 完成长任务、跨重启、工具故障、用户插话、人员调整和真实交付验收。
- 发布前完成安装覆盖、回滚、GitHub Release 和交接记录。

## 7. 必须通过的场景验收

1. 配置 IMA：主动阅读说明、检查环境、配置连接器、缺凭据时只询问必要信息，不能运行上百步重复读取 Skill。
2. 天气查询：围绕指定时间地点获取天气证据，不搜索地方特征，不读取无关本地文件。
3. 软件项目：先确认关键方向，正确组队，动态规划，真实写入、运行、审查、返工和交付。
4. 用户插话：执行中立即回应；补充要求进入当前目标，独立目标建立新项目，暂停后不私自恢复。
5. 失败恢复：相同失败路线不超过两次，随后换路线或通俗说明需要用户做什么。
6. 动态补人：项目中途增加员工后修改同一名单和计划，不重建团队、不丢原工作区。
7. 外部服务故障：HTTP 5xx 保留现场并等待恢复，不误报为没有 API、没有工作区或用户配置错误。
8. 重启恢复：关闭聊天窗口或客户端不等于暂停；重启后继续同一 `goalId`、计划版本和证据现场。
9. 证据完成：没有文件、运行、连接测试或人工确认等所需证据时绝不能声称完成。
10. 权限边界：密码、验证码、付费、删除和对外发送始终在动作前请求确认。

## 8. 量化门禁

- 目标保持准确率不低于 98%。
- 任务语义基准不低于 98%，并持续增加真实失败反例。
- 无关工具或无关员工进入率低于 1%。
- 完全相同的失败工具调用连续次数不得超过 2。
- 无证据完成率必须为 0。
- 用户纠正后继续旧错误路线的比例必须为 0。
- 可恢复任务跨重启现场恢复率必须为 100%。
- 真实项目必须统计用户介入次数、路线变更次数、有效工具比例、完成证据和总耗时。

## 9. 防跑偏检查清单

每次设计、编码、审查和发布前必须逐项回答：

- 这项修改增强的是目标理解与自主解决，还是只增加了一个固定分支？
- 模型是否仍有根据新证据换路线的空间？
- 确定性代码是在守事实与安全边界，还是替模型做完整语义决策？
- 当前计划能否局部修改，还是必须全部重来？
- 用户插话是否进入同一目标状态并立即得到回应？
- 失败后是否先归因，再决定重试、换路线或请求用户？
- 完成是否由真实证据决定？
- 新增状态是否持久化并可跨重启恢复？
- 助手、员工私聊和团队入口是否使用同一核心协议？
- 是否保留旧用户数据与回滚路径？

任意一项答案为否，不能宣称对应自主能力已经完成。

## 10. 明确禁止的做法

- 不得继续用更长提示词冒充内核升级。
- 不得针对单个截图增加一次性关键词补丁后宣称解决同类问题。
- 不得用固定员工白名单代替能力判断。
- 不得用固定 DAG 步骤数量衡量项目进展。
- 不得用模型调用次数、工具次数或“正在处理”心跳冒充真实进展。
- 不得把所有失败统一成重试，或达到预算后直接宣称完成。
- 不得展示或保存隐藏思维链；只展示公开决策摘要和证据。
- 不得为了追求自主性绕过沙盒、审批、凭据和不可逆操作边界。
- 不得在没有真实端到端验收时给自主能力打高分。

## 11. 开发顺序

1. 先写数据合同、事件协议、迁移和回归样例。
2. 再以影子模式接入现有真实项目，比较新旧决策差异。
3. 通过真实回放验证后，逐入口替换主持权。
4. 每阶段同时覆盖助理、员工私聊、团队和后台恢复。
5. 每个大版本完成后执行门禁、打包、覆盖安装、真实项目验收、GitHub 发布和 `handoff.md` 交接。

这份文档是后续自主智能体升级的方向合同。新增 UI、Skill、连接器或员工功能不能中断该主线；临时问题可以修复，但不得借修复重新强化固定工作流对目标决策的控制。
