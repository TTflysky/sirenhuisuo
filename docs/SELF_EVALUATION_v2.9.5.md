## 已验证优势

1. **任务不是单轮聊天。** 任务合同、执行账本、暂停恢复、用户插话、证据、检查点和未决问题可被持久化与回放。
2. **团队不是角色扮演。** 专家目录、职责、项目 DAG、补人、替换负责人、定向返工和验收条件已有结构化数据边界。
3. **编码有独立执行设施。** 代码工作区、Git Worktree、原子补丁、符号与依赖定位、测试选择、命令日志和回滚点不依赖模型口头描述。
4. **完成需要证据。** Skill、连接器、网页、文件和代码交付不再只依据模型的完成声明。
5. **可观测性已具备基础。** 任务、工具、模型、连接器、错误类型、持续时间、预算和诊断导出均有记录边界。
6. **模型能力可被约束。** 聊天、诊断和图片模型按能力过滤；本版进一步修复了 HTTP 503 的分类和恢复表达。
7. **发布有工程门禁。** Windows 构建、包内检查、SBOM、来源证明、版本一致性和远端资产哈希校验被纳入发布流程。

## 主要短板与影响

1. **语义泛化仍不足。** 200 条基准中 195 条通过，剩余 2.5% 说明含糊引用、并行目标和长插话仍可能让模型选错当前目标或工具。
2. **核心模块仍然过大。** `hermesClient.ts`、`nativeExecutionAdapter.cjs`、`store.tsx` 贴近边界上限，修改风险和回归成本仍高。
3. **上游服务韧性不足。** HTTP 503 已能被准确解释和恢复，但没有多供应商熔断、健康探测和可控降级，用户仍会受供应商可用性影响。
4. **外部生态缺少实机矩阵。** 模型、图片、Skill、MCP、知识库、邮件和 GitHub 的真实账号路径尚未逐类通过成功、鉴权失败、限流、协议变化与恢复用例。
5. **长时间 Electron 稳定性未证明。** 仅有短驻留和确定性性能基线；8 小时后台、多窗口和 GPU 异常场景没有正式报告。
6. **更新回滚尚未演练。** 更新事务和回滚代码存在，但未从已发布旧版完成下载、迁移、故障注入、回滚和业务数据核对。
7. **前端性能仍有债务。** 主 JS 包约 5 MB，存在无效动态导入和分包告警，长任务下的首字反馈、内存与渲染成本仍需优化。
8. **安全治理仍是个人客户端级别。** safeStorage 和脱敏已落地，但没有组织级 Vault/KMS、短期凭据轮换、多租户隔离和完整审计留存。
9. **在线安全审计未刷新。** 当前网络不能访问 npm 审计端点，不能把离线构建通过解释为依赖风险已清零。
