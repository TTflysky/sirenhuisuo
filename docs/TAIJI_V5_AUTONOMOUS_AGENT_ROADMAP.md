# 太极 V5 自主智能体团队升级路线

## 总目标

V5 的目标不是为某一个项目增加特例，而是把太极从“套着聊天界面的固定工作流”升级为自主智能体协作团队。运行时必须根据目标、证据、阻塞和用户插话动态决定下一步；生命周期状态可以使用状态机，但状态机不得规定所有项目的固定执行顺序。

## 不可偏离的边界

- 新聊天默认独立 `conversationId`，长期记忆可以共享，任务和审批只有用户明确继承时才关联。
- 每个聊天或项目拥有独立 `projectId`、项目文档和工作区，文件、浏览记录、任务和产物不得跨项目平铺或检索。
- 团队提案必须可版本化、可替代、可取消；旧审批失效后不能继续显示为可批准方案。
- 成员增删替换必须是结构化变更，并留下审计记录。
- 成员的通知不等于完成；每名成员必须有真实子任务、状态、回应和证据。
- 普通读取、搜索、写入和验证由智能体自主完成；外部授权、付费、删除、发送和敏感操作才需要用户确认。

## 统一实体

`Conversation`、`Project`、`Proposal`、`Team`、`Membership`、`Workspace`、`Task`、`Subtask`、`Artifact`、`Approval`、`Evidence`、`Memory` 和 `AuditEvent` 都必须拥有稳定 ID，并通过事件账本和可恢复快照长期保存。

## 项目文档与工作区

每次新建聊天或项目自动建立独立项目文档：

```text
projects/<projectId>/
  project.md
  project.json
  conversations/<conversationId>.md
  tasks/<taskId>.md
  artifacts/{final,working,reference,logs}/
  evidence/
  events.jsonl
```

`project.md` 记录目标、约束、验收标准、成员、提案和审批版本、任务过程、成员回应、产物路径、证据、未决问题和下一步。界面统一提供“概览 / 工作空间文件 / 浏览器”三个项目范围内的入口。

## 阶段路线

### V4.1：目标与实体边界

建立统一 `GoalFrame`，补齐 `conversationId`、`projectId`、`workspaceId`、`proposalRevision` 和继承策略，修复新聊天被旧任务语义污染的问题，并提供 V4 数据迁移和回滚。

### V4.2：项目文档与工作区隔离

新聊天生成项目文档，新项目生成独立工作区；文件、浏览器、日志、任务和产物全部按项目归档；重启后能够恢复同一项目的完整上下文。

### V4.3：提案、审批与成员生命周期

支持草案、待确认、已批准、已替代、已取消和已组建；纠正成员时生成新 revision；旧批准卡立即失效；支持加人、删人、换人和审计。

### V4.4：动态 Agent Runtime

用目标、假设、行动和证据组成可修改目标图。独立行动可以并行，依赖行动等待证据；失败后自主换工具、换路线或请求用户，不允许无限重复固定步骤。

### V4.5：真实协作与产物中心

每位成员拥有真实子任务和响应状态；“请大家规划”必须产生成员规划回合；产物绑定项目、任务、成员、路径和证据，并支持预览、打开文件、打开目录和复制路径。

### V4.6：插话、恢复与自我纠错

插话先判断新需求、当前任务修改、暂停、取消或状态询问；已完成证据保留，未完成目标重新评估；失败经验进入审核队列，批准后才进入长期记忆。

### V5.0：整体验收

覆盖多聊天、多项目、提案替换、成员管理、工作区隔离、动态并行、失败换路、真实产物、重启恢复、记忆边界、安全审批、升级和回滚。

## V5 新增交互要求

- 新团队建立后，先开启成员规划回合，每名成员在群里说明职责、初步方案、依赖和风险，用户可以在正式执行前修改。
- 团队群中的助理显示“排队 / 思考中 / 回答中 / 出错”状态，并使用动态点提醒；状态必须来自真实模型请求，不得用静态假象代替。
- 每个阶段完成后，助理主动发布阶段总结：已经完成、尚未完成、证据、阻塞原因和下一步负责人。
- 升级检查和升级操作只放在“设置 → 诊断中心”，首页不再展示升级按钮。

## 每次执行前的路线门禁

1. 回顾本文件和上一阶段 handoff。
2. 写明本阶段目标、非目标和验收证据。
3. 检查改动是否为单项目特例，若是则退回重做。
4. 完成构建、测试、回放和迁移验证后更新 handoff 与 CHANGELOG。
