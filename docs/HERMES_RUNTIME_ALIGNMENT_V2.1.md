# 太极 v2.1 与 Hermes 真实运行链路对齐

> 太极版本：`v2.1.0`  
> Hermes 参考提交：`41a07f5b8451f88a8b8b5adfc0cfdc2ada0a1f90`  
> 对齐日期：2026-07-29

## 边界

这次升级只吸收 Hermes 在真实执行链路中的职责划分和恢复语义，不复制 Hermes 的品牌、界面、Python 工程、CLI、供应商适配器或隐藏思维链。太极继续使用 Electron、React、TaskService、原生 Worker、员工与团队、Skill、Connector、人格和现有本地存储。

兼容边界保持不变：员工、团队、聊天、模型、人格、记忆、任务账本、工作区以及 `hermes_office_*` 本地存储键不会重命名或清空。

## 四层真实运行链路

### 1. 模型决策与公开轨迹

Hermes 的 `conversation_loop.py`、`turn_context.py` 和 `turn_finalizer.py` 让同一个模型在每次真实观察之后继续决定下一步，并在所有退出路径统一收尾。太极对应实现为：

- `src/engine/turnRuntime.mjs` 保存目标、模型公开决定、证据缺口、精确工具参数、错误分类、恢复动作和验收结果。
- `src/engine/turnLifecycle.mjs` 保存不含隐藏思维链的公开行动轨迹：目标、模型公开决定、工具调用与结果、插话、上下文、预算、退出原因和恢复条件。
- `src/data/hermesClient.ts` 在助手与员工私聊的模型请求、公开决定、工具开始、工具结果、压缩、插话和收尾处推进同一协议。
- `electron/nativeExecutionAdapter.cjs` 在团队原生 Worker 使用同一协议，不再依赖聊天气泡推断任务事实。

轨迹使用单调 `sequence`。TaskService 拒绝旧序号和同序号冲突快照，避免旧窗口或延迟 IPC 把新进度覆盖回去。生命周期在渲染端和主进程各脱敏一次，API Key、Token、Cookie、密码、Bearer 凭据和 URL 查询凭据不进入账本。

### 2. 执行循环与分类恢复

Hermes 的 `turn_retry_state.py`、`iteration_budget.py`、`error_classifier.py` 和 `turn_finalizer.py` 将重试、预算和退出统一处理。太极对应实现为：

- 助手、员工和团队共享认证、授权、计费、限流、网络、超时、上下文溢出、参数错误、依赖缺失、结果偏题和验收失败分类。
- 相同失败路线受有限恢复次数和重复指纹约束，不能靠反复调用同一工具伪装进展。
- `completed`、`waiting_user`、`paused`、`checkpointed`、`stopped` 和 `failed` 是不同结局；等待用户或预算检查点不再记成普通失败。
- 进程心跳只证明执行器仍存活，`progressAt` 只由模型决定、真实工具结果、插话处理或上下文推进刷新。
- 暂停、等待用户、停止、失败和预算检查点都生成恢复胶囊；停止可以覆盖正在处理的暂停，避免控制竞态。

### 3. 工具与 Skill 真实调用

Hermes 的 `tool_executor.py` 和 `tool_result_classification.py` 以 `tool_call_id` 原子配对模型动作与工具结果。太极对应实现为：

- 模型负责工具选择和业务参数，运行时只校验工具存在性、Schema、权限、安全、审批、重复和预算，不改写搜索词或文件目标。
- 每个工具调用以 `callId` 记录开始和结果；恢复时若发现已经有真实证据但调用仍显示进行中，会闭合同一记录，不复制调用。
- 完整结果进入原有证据与任务账本，生命周期只保存脱敏摘要、结果引用和证据 ID。
- Skill 安装继续使用原生原子安装器，完成安装、回读和健康检查后才能作为成功证据；Skill 与 Connector 通过统一工具注册和协议参与循环，不增加主题硬编码路线。
- 子任务只继承父任务已验证的产物、引用和生命周期恢复胶囊，父任务未验证的口头声明不能变成子任务事实。

### 4. 记忆与团队协作闭环

Hermes 的 `context_compressor.py`、`memory_manager.py`、`moa_loop.py` 和 `subagent_lifecycle.py` 分别负责可恢复上下文、后台记忆、顾问隔离和子代理生命周期。太极对应实现为：

- 压缩保留当前目标、工具调用与结果配对、已验证证据、未决问题、用户插话和预算，不只保留“做过某事”的文字摘要。
- `conversationId` 贯穿助手、员工、团队、TaskService 和子任务，新聊天不会接收旧任务迟到结果。
- 子任务继承父任务目标、验收标准、已验证引用、生命周期退出原因和恢复胶囊；父子任务继续、暂停和停止保持正确顺序。
- MoA 顾问只提供建议，不调用工具、不改变状态、不宣布完成；真实员工拥有独立子任务、预算、工作区、工具证据和终态。
- 生命周期恢复胶囊与现有长期记忆分层：前者保存“这项任务下一步怎么继续”，长期记忆只保存稳定偏好和经验证经验，二者不能互相冒充。

## 本版验证合同

`npm.cmd run verify:turn-lifecycle` 覆盖：

- 工具开始与结果按 `callId` 配对。
- 中断恢复后用真实证据闭合进行中调用。
- 上下文压缩保留目标、用量、证据和未决问题。
- 用户插话进入恢复胶囊。
- `waiting_user` 可继续且不等于失败。
- 渲染端和主进程双重凭据脱敏。
- 旧序号和同序号冲突快照不能覆盖新事实。
- 助手、员工私聊和团队原生 Worker 均接入同一协议。

该检查已加入 `verify:v2-core-gate` 和 GitHub 发布脚本。正式发布仍需同时通过 `verify:v1-core-gate`、构建、包内资源校验和安装包哈希校验。

## 后续保留项

本版没有假装完成 Hermes 的所有外围生态。以下内容按太极产品边界继续独立演进：

- 助手和员工聊天进一步迁移为完全由主进程托管的长期后台队列。
- 对真实模型、真实网络、真实 Connector 的小规模在线冒烟由有可用凭据和稳定网络的发布环境执行。
- Git 工作树按代码任务按需创建，不强制所有普通办公任务承担仓库开销。
- 外部记忆供应商保持可选；本地记忆和任务恢复不能依赖第三方服务才可工作。

这些保留项不能降低本版已建立的轨迹真实性、工具配对、分类恢复和数据兼容要求。
