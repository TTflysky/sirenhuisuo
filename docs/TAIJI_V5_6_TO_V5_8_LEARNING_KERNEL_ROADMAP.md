# 太极 V5.6 至 V5.8 学习内核路线图

更新时间：2026-08-07

## 终点与边界

太极的下一阶段不是增加更多固定工作流，也不是把历史问题堆进更长的提示词。目标是让平台能从真实项目中形成可追溯、可撤销、可验证的经验，并把真正重复且成功的流程沉淀为受控 Skill。

必须始终满足：

- 新聊天默认是独立 `conversationId`、`projectId` 和工作区；项目事实不得自动污染别的项目。
- 模型能决定策略，但事实、权限、证据、审批和状态由内核记录并约束。
- 记忆、Skill 候选、草案、发布和回滚均有稳定 ID、来源任务和证据链。
- 不为某个 Skill 名称、网站、项目标题或一句用户措辞写特例。
- 每个版本开始前回顾本文件和 `handoff.md`；每个版本结束后必须写复盘、验证证据、未决问题和下一版本决策。

## 当前基线（V5.5.3）

已具备分层记忆、复盘队列、Skill 草案隔离目录、人工批准、原子安装、任务证据和项目工作区等基础能力。它们已通过专项脚本验证，但还没有构成一个统一、可解释的长期学习系统。

当前主要风险：

- 旧版用户画像、用户记忆和任务经验仍由渲染端 `localStorage` 直接读取，和主进程分层记忆形成双事实源。
- 记忆没有 `project` 范围，可能把一次项目的经验写到组织或团队层后影响新项目。
- 模型上下文只得到拼接后的记忆正文，缺少“本次引用了哪些记忆、为什么命中”的证据。
- Skill 草案可由一次复盘直接生成 Markdown；缺少跨任务候选聚合、契约校验、安全扫描、演练和灰度观察。

## V5.6：统一记忆账本与项目边界

### 目标

让主进程记忆账本成为唯一可写事实源，新增项目范围、引用审计、冲突替代和兼容迁移。模型可以检索记忆，但不能绕过账本直接把长期经验写回浏览器存储。

### 必做

1. 统一 `MemoryRecord`：`memoryId`、`scope`、`scopeId`、`projectId`、`kind`、`content`、`evidenceIds`、`sourceTaskId`、`confidence`、`importance`、`status`、`supersedes`、`reviewAfter`。
2. 新增 `project` 范围，并把项目 ID 传入助理、员工私聊、团队讨论、任务恢复和复盘队列。
3. 将旧 `userMemory`、`userProfile`、`taskLearningMemory` 作为一次性兼容导入来源；导入后只保留只读备份，不再作为模型上下文来源。
4. 记忆检索返回正文、`memoryIds`、命中分数和命中原因；这些引用写入任务/会话证据账本。
5. 项目记忆默认不跨项目。提升为团队、组织或用户记忆时必须生成带证据的提案；不得静默提升。
6. 仅当存在真实验收证据时，才允许团队/员工的程序性经验自动写入。组织和用户范围始终需要人工批准。
7. 支持查看冲突条目的来源、替代关系和回滚路径。

### 非目标

- 不引入向量数据库，不用“语义搜索”掩盖事实源和边界问题。
- 不自动把全部旧 `localStorage` 数据删除。
- 不改变用户手工录入内容的语义；仅迁移存储位置和审计方式。

### 验收

- 新项目不读取旧项目专属记忆。
- 一次模型调用可追踪其引用的记忆 ID 与命中理由。
- 同一事实发生替代后可回看旧版本、来源、替代原因并撤销。
- 重启、导入和迁移后数据一致，旧浏览器键不再参与模型上下文。

## V5.7：Skill 候选、编译、验证与灰度

实现状态：已于 V5.7.0 完成源码与自动验证。真实长期复用统计和客户端长驻属于 V5.8，不在本阶段冒充完成。

### 目标

把“模型在复盘时写一段 Markdown”升级为“有真实证据、可验证、可审阅、可回滚”的 Skill 生命周期。

### 必做

1. 新增 `SkillCandidate`：`candidateId`、`projectId`、来源 `taskIds/evidenceIds`、路线指纹、跨任务次数、成功率、失败模式、权限、风险和状态。
2. 只有满足硬条件才能进入草案：至少两项独立任务、存在真实验收、工具路线相近、失败率低于阈值。
3. Skill 编译器生成结构化 metadata、权限声明、输入/输出契约、成功标准和可选 `scripts/`、`references/`、`agents/openai.yaml`。
4. Skill 结构遵循渐进加载：核心说明简洁，易错且确定的操作以脚本或低自由度步骤承载；参考资料按需加载。
5. 草案验证流水线：frontmatter/schema、权限核对、敏感路径与凭据扫描、依赖声明、dry-run、正向样例和失败样例。
6. 审批页面展示正文、Diff、来源任务、证据、权限、风险与测试报告。
7. 批准后先灰度：记录首次调用、成功率和失败类型；超过阈值自动停用，支持回滚到上一版。

### 非目标

- 不允许模型自动覆盖内置或手动安装的 Skill。
- 不把单次任务的临时方案伪装成通用 Skill。
- 不允许 Skill 获得超出原始任务证据所证明的权限。

### 验收

- 一次性任务不会生成可安装 Skill。
- 合格候选能在审阅前展示来源、权限、测试与风险。
- 灰度失败能够自动停用并保留完整证据。

## V5.8：真实自治评测与持续学习

### 目标

用可回放的长期任务证明学习内核，而不是只用单元测试证明局部模块。

### 必做

1. 建立 20 至 30 个可回放场景：项目隔离、文件产物、团队补人、用户插话、模型/工具失败、恢复、记忆冲突、Skill 灰度和回滚。
2. 记录完成率、误执行率、恢复率、记忆命中正确率、跨项目污染率、Skill 复用成功率和不必要工具调用数。
3. 加入真实客户端长驻留、多窗口和大量员工回归。
4. 每版产出自评、能力矩阵、失败样本、改进决策与发布证据。

### 验收

- 在连续任务和大量员工场景下，项目记忆不串台，失败可恢复，Skill 可回滚。
- 每个正式版本均能追溯到完整评测结果与发布材料。

## 版本复盘门禁

每个版本结束前必须回答并写入 `handoff.md`：

1. 本版目标是否完成，哪些不在范围内。
2. 通过了哪些自动验证和真实运行验证，哪些尚未执行。
3. 发现了哪些失败样本，根因属于模型、事实、权限、工具、状态还是界面表达。
4. 自评分与上版相比为什么升降；不得只报总分。
5. 下一版只解决哪一个已证明的短板，避免跨阶段混做。

## 当前执行顺序

V5.6 与 V5.7 已完成，下一阶段只进入 V5.8 的真实自治评测与持续学习。不得为了提高评分重新回到单次任务自动生成 Skill，也不得用短时脚本代替长期客户端证据。
# V5.8 Status (2026-08-07)

V5.8 source work is complete pending the final release gate. The release now contains a 24-scenario evaluation ledger, runtime task/memory/Skill evidence capture, Diagnostics Center controls, the v29 default persona protocol, and a 12-window real Electron residency smoke test. Automated replay and short residency are not long-running field evidence. The next work after release is to collect a real accompaniment session and choose one verified weakness from its evidence.
