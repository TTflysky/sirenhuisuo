# 太极大版本：Hermes Agent 公开文档对照

> 调研日期：2026-07-26
> 来源：Hermes Agent 公开安装、快速开始、更新、配置、功能概览、CLI 与贡献指南。
> 结论：参考工程理念，不接入、安装、复制或改造成 Hermes Agent。

## 已阅读范围

- 安装：前置条件、Windows PowerShell、小白步骤、配置目录、API Key、提供商配置、最终验证和故障排除。
- 快速开始：终端、会话恢复、中断、技能、自动化、消息平台、MCP/ACP。
- 配置：配置优先级、环境变量、终端后端、持久 Shell、技能、记忆、文件安全、Git 工作树隔离、上下文压缩与预算警告。
- 功能概览：核心 Agent、自动化、媒体与网络、自定义能力。
- 更新：版本检查、更新后验证、手动更新、回滚与卸载。
- 开发者指南：跨平台、编码、进程、安全、提交前检查与贡献流程。

## 可吸收并纳入太极

| 主题 | 太极实现方向 | 优先级 |
| --- | --- | --- |
| 前置检查与安装验收 | 所有任务使用“前提 → 执行 → 验证”状态，不把下载或单命令成功当作最终成功 | P0 |
| 配置优先级 | 明确全局模型、助手模型、员工模型、连接器配置与本地用户数据的优先级和覆盖提示 | P0 |
| 任务预算与上下文 | 统一上下文压缩、执行预算、无进展停止和强制交接 | P0 |
| 技能完整性 | 以目录清单安装 Skill，校验 `SKILL.md`、参考资料、脚本、依赖、授权和来源状态 | P0 |
| 工作区隔离 | 每个助手/员工/团队任务具备可追溯工作区；后续加入 Git 工作树隔离 | P1 |
| 诊断能力 | 模型、连接器、技能和任务均提供小白可读的预检、原因和修复入口 | P1 |
| 更新后验证 | 每次升级自动验证包内版本、数据迁移、技能数量和核心窗口可打开 | P1 |
| 安全边界 | 文件路径、命令、凭据、外部连接器和用户授权分层处理 | P1 |
| 跨平台工程约束 | 保持 Windows 作为首要目标，同时避免写死路径、编码和进程行为 | P2 |

## 已同质化，保留并统一

- 多员工、多模型、团队协作、审批式项目草案与任务顺序执行。
- 助手的目标理解、前置判断、失败诊断、换路线、最终自检和通俗交接。
- 独立桌面窗口、员工私聊、团队聊天、附件落盘、产出物归类。
- 内置/我的/市场 Skill、网页知识库、Obsidian 入口和外部连接器。
- 主题、字体、员工卡片、头像、身份牌和状态可视化。
- GitHub Releases 自动更新、安装包验证和本地数据保留。

## 暂不采用

- Hermes CLI、斜杠命令与终端优先交互：太极保留桌面图形界面作为主入口。
- WhatsApp 等消息网关：尚不进入当前办公协作核心。
- 语音、TTS/STT、ACP、插件网关：记录为后续扩展，不在本大版本提前堆入。
- Docker/SSH/Modal/Daytona 等多终端后端：先建立太极本地工作区安全模型，再评估按需接入。
- Hermes 的目录、配置名、品牌、安装器、默认提示词和 UI：全部不采用。

## 太极大版本实施顺序

1. 完整目录 Skill 安装器、技能清单与健康状态。
2. 统一任务状态机：目标、前提、证据、产出、验收、阻塞和交接。
3. 模型/连接器/技能预检与“用户现在需要这样做”引导。
4. 工作区与任务记录隔离，保留后续 Git 工作树能力接口。
5. 太极品牌迁移及数据兼容。
6. 更新后自检和一键诊断中心。
