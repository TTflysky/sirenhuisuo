# v0.51.0 TaskService

## 目标

把助理、员工单聊和团队任务统一到主进程的任务账本。聊天消息不再是任务状态的唯一来源，模型文字也不再直接等于“已完成”。

## 任务记录

每个任务都具备：

- `taskType`: assistant、dm、team 或 child
- `parentTaskId`: 子任务与父任务的真实关系
- `steps`: 步骤、依赖、执行人、尝试次数和状态事件
- `toolAttempts`: 工具名称、状态、错误分类、结果摘要和证据引用
- `artifacts`: 最终产物、工作产物、参考资料及是否已验证落盘
- `references`: Skill、网页、文件、连接器等后续可引用对象
- `acceptanceCriteria`: 任务完成标准

## 持久化

TaskService 复用 Electron 主进程已有的哈希链任务账本和恢复点，不在渲染进程另存一套状态。应用重启后从 `task-events.jsonl` 回放任务投影，快照只作为读取优化。

## 幂等

创建任务时可提供 `idempotencyKey`。同一作用域内重复提交相同键只返回原任务，不创建重复任务。创建员工子任务时默认使用父任务、员工和标题组合键。

## 完成判定

本版本只建立真实记录入口，尚未把所有旧聊天入口迁移到 TaskService。v0.52 将统一工具执行协议，v0.55 才会把动态团队调度完全迁移到原生子任务控制面。

## 验收

运行 `npm.cmd run verify:task-service`，必须验证：任务创建、重复提交、工具尝试、引用、交付物、子任务、状态变化、重启回放和账本完整性。
