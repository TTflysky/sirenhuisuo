## 30 秒了解太极

太极不是只有聊天框的 AI 客户端。用户可以在办公室中配置不同模型和专业员工，由章北海助理理解目标、组建团队、编排可恢复计划，并让成员在隔离工作区中查资料、写文件、运行命令、审查证据和交付结果。任务的状态、授权、重试、阶段交接和产出物都保存在本机，可在中断后继续。

### v3.7.0 动态计划与自主恢复

- 任务计划升级为可持久化、可迁移和可回放的 `AdaptivePlanGraph`；计划具有稳定 ID、版本号、修订历史、路线历史和人员变更记录。
- 助理可以通过正式工具修改同一份计划：增加或更新节点、调整依赖、换人、局部重开、废弃节点和切换执行路线；不再靠复制整份任务伪装成恢复。

### v3.0.0 阶段 A：语义决策与模型韧性

- 任务决策拆为候选理解、上下文约束、风险/证据校验和可执行计划四层。每层保存有限输入、接受结果和运行时拒绝原因，并随任务合同持久化；它是可交接审计，不包含隐藏思维过程。
- 语义基准从 200 条扩展到 400 条，新增指代、目标切换、纠错、团队协作、附件、指定资源、连接器和暂停/继续/停止反例；当前目标、关系和首选路线为 `400/400`，发布门槛固定为不低于 98%。
- 模型运行期增加健康登记、连续故障熔断、半开探测、确定性指数退避和备用模型建议。系统不会静默换模型；保护窗口保留当前任务现场并阻止重复请求。
- 每次聊天模型调用记录总耗时、流式首 token、成功率、HTTP 状态、503/429/超时/网络分类和恢复结果。诊断中心显示这些运行期指标，不保存 API Key。

### 稳定任务闭环

- `v2.1.0` 按 Hermes 真实运行链路补齐持久 Turn Lifecycle：模型公开决定、工具调用/结果、上下文压缩、插话、预算、退出原因和恢复条件在助手、员工私聊与团队中使用同一协议；详细对齐见 [`docs/HERMES_RUNTIME_ALIGNMENT_V2.1.md`](./docs/HERMES_RUNTIME_ALIGNMENT_V2.1.md)。
- 用户原始目标是不可改写的事实源；模型在每个真实结果后重新判断下一步，运行时不会把搜索词、文件目标或连接器参数替换成整段任务。
- 联网搜索不再以“返回了若干网页”作为成功。偏题、过期或缺少关键条件的结果会作为失败证据回注模型，由模型换查询词、换来源或形成明确交接，不再拼凑答案。
- 助理、员工私聊和原生团队执行共用 Turn Runtime：观察、行动、工具结果、错误分类、恢复、插话、上下文压缩和最终收尾使用同一协议。
- 回答、文件、连接、操作、决策和混合任务分别验收。普通问答不再被强制生成文件，连接器也不能用一份说明文档冒充连接成功。
- 团队按稳定能力图做最小覆盖选择；UI/UX、前端实现、后端、调研、办公文档、连接器、Skill、工程、审查和协调能力彼此区分。
- 复杂团队步骤可使用 MoA 私有顾问。顾问只能提供风险与验收建议，不能调用工具、改变任务状态或对用户宣布完成。
- 新增统一“任务决策内核”：每条消息先编译为聊天、直接回答或执行任务，并形成真实目标、首选路线、完成标准和用户条件；它独立于人格提示词，助手、员工私聊、团队和自主任务共用。
- 任务合同会强制约束后续工具循环；模型不能把“调用过工具”“列过步骤”当成完成。明确的外部查询、本地文件、连接器、文件产出与命令任务有客户端高置信度保护，模型误判时会被纠正。
- 新增任务经验记忆：执行后只保存可复用的成功路线、失败类型和验收结果；相似任务开始前会检索经验，避免重复卡在同一条无效路线。设置中的“记忆”页可查看或清空任务经验。
- 新增组织、团队、员工、用户四层结构化记忆。团队共享经验和员工独立经验同时参与下一步执行，当前明确要求始终高于旧记忆。
- 终态任务会进入异步复盘队列：真实验收路线直接沉淀，模型推断先进入记忆建议，重复稳定流程只生成隔离 Skill 草案，均不会在后台静默改写内置或手动 Skill。
- 助理、员工私聊和团队任务共享统一 `ExecutionController`：每一步都会观察真实结果、判断进度、分类失败、选择重试或换路线，并在结束前重新验收最初目标。
- 模型请求和工具错误按认证、授权、计费、限流、超时、网络、服务端、上下文、参数、依赖和验收失败分类恢复；自动恢复有明确上限，不能靠反复调用同一工具假装推进。
- 只有账号凭据、登录授权、审批或业务选择等客户端无法自行取得的条件才会暂停询问用户；普通失败由系统先自动诊断并尝试替代路线。
- 助手、员工私聊和团队任务每次请求都使用独立工作区；任务恢复沿用原目录，不会与另一项任务的同名文件互相覆盖。
- 设置首页提供统一诊断中心，一次检查模型、连接器、Skill、工具、任务内核、工作区和审批策略，并告诉用户缺什么、去哪里处理。
- 团队任务持久化摘要、证据、未决问题、运行中插话和上下文预算；客户端异常退出后会进入“待恢复”，不从头重跑。
- Skill 安装前展示账号、环境变量和外部软件要求；损坏 Skill 会隔离，来源明确的用户 Skill 可一键修复。
- 文件、运行、连接、审查和人工确认分别记录验收证据；模型口头说“完成”不会把任务直接标记为完成。
- 连接器统一执行输入校验、权限、预检、真实调用和输出校验；协议证据包含失败阶段、错误分类、耗时与幂等命中，团队界面只信任客户端事件。
- 文件写入、命令生成文件和审查结论统一产生客户端结构化证据；团队面板显示真实路径、交付类别、大小、落盘验证和计划图事件。
- 审查者必须通过 `submit_review` 提交机器可读结论；退回会把责任步骤、修订步骤和复审步骤正式写入 Plan/Runner，暂停或重启后仍能从正确节点继续。
- 长任务上下文升级为 v2：保留最近 120 条结构化事件，同时生成确定性压缩摘要；达到阈值后由助理模型补充导航摘要，模型摘要不能覆盖结构化事实。
- 新任务会检索相似的已完成、失败、停止或暂停任务，只读复用已验证事实和交付路径；旧任务不能覆盖当前目标、输入或验收标准。
- API Key、Token、密码和验证码不会进入工具展示；删除、付费、外发和凭据操作始终需要单独确认。
- 更新前加密备份本地配置，更新后核对员工、团队、模型、任务和工作区；回滚安装包沿用客户端系统代理，支持断点续传和网络重试，完整大小与 SHA-256 校验通过后才恢复配置。
- 应用包名、Windows `appId`、安装目录和用户数据目录已统一为“太极”；首次启动会无损复制旧目录中的员工、团队、聊天、任务、记忆和工作区，`hermes_office_*` 旧存储键仅作为历史数据兼容层保留。

### 多员工、多模型协作

- 每个员工都可以拥有独立身份、职责、提示词、人格资料和模型配置。
- 员工关闭“独立模型配置”时，继承全局激活模型。
- 员工开启“独立模型配置”后，可以引用模型库或手动填写接口。
- 同一个团队可以同时使用多个不同模型，适合规划、编码、审查等岗位分工。
- 助理模型、全局模型和员工独立模型彼此有明确边界，不会被最后一次切换全员覆盖。
- 助手和员工默认面向非技术用户回答：先说清楚成功或失败，再说明在哪里使用或卡在哪一步；技术日志只放在折叠执行过程中。

### 助理监督与任务调度

- 章北海助理默认接收没有明确点名的团队消息。
- 明确 `@员工` 时由该员工处理，助理不会无故抢答。
- 工作请求会形成真实任务计划，并按照步骤依次执行。
- 上一步没有结果或模型超时时，后续步骤不会直接跳过。
- 审查不通过时，任务退回对应责任员工修改，再次提交审查。
- 任务可暂停、继续、停止或关闭记录，并保留已经完成的内容和执行证据。
- “暂停工作、汇报模型、汇报状态、报数”等控制指令不创建任务，也不调用 Skill 或文件工具。
- 运行中可继续发送消息；最新消息会先中断正在等待的模型，执行策略支持“引导当前运行”或“排队处理”。
- 聊天中直接说“暂停 / 继续 / 停止”与按钮同权；暂停中可以回答新消息，但不会因此恢复旧任务。

### 人格、画像与长期记忆

- 章北海助理的人格只定义职责、工具和行为边界；用户画像由用户主动维护，不会被自动分析覆盖。
- 长期记忆只提炼稳定身份、长期偏好、明确约束、工作流程和已确认决策，过滤临时任务、闲聊和工具错误。
- 记忆支持分类、重要性、置信度、相似去重、冲突替换和旧数据一键整理。
- 同步配置现在同时携带人格、用户画像、长期记忆和任务经验；API Key、密码、Token 等本机密钥仍自动脱敏，不会写入同步文件。

### 可观察的执行过程

- 聊天气泡显示时间和 Token 消耗。
- 模型选择器显示本次输入上下文、已设置的上下文上限和占比；接口未返回用量或上限时会明确标注为估算或未知。
- 实时执行区只突出当前动作并跟随窗口宽度；当前项可展开查看输入，完成后自动归入折叠记录。
- 助理窗口关闭后任务会继续在后台执行；主界面持续显示当前动作、真实完成数和运行时间，并提供暂停、继续、停止入口。
- 执行过程默认收起，历史步骤可逐条展开查看通俗结果和技术详情，不再铺满聊天窗口。
- 助手运行中收到用户插话时先结合真实进度回答，再调整当前执行或排队接续；“这种操作没有意义、一直重复”等反馈会挂起旧任务，不再机械续跑。
- 执行过程按受控阶段压缩保存；Skill 失效会自动重检本机、查询替代资料并改走通用工具，只有确实需要账号、授权、文件或业务选择时才向用户交接。
- 连接器任务最多执行 24 次工具尝试；同一个 Skill 只真实读取一次，重复调用、资源反复读取和长期只搜索不行动都会被内核熔断并强制换路线或交接。
- 右侧任务列表收纳进行中和已完成任务，默认收起，点击后展开。
- 右侧任务栏支持跨团队、跨会话历史任务检索；任务详情提供只读回放，按时间展示上下文与 Runner 事件。
- 任务运行状态写入主进程追加式 JSONL 事件账本；事件带严格序号、来源、会话、状态迁移、变化域和 SHA-256 哈希链，任务回放优先显示账本事实。
- `task-runs.json` 只作为启动加速用投影缓存；客户端重启会从事件账本重建，旧版快照自动迁移，损坏尾部会隔离并保留有效历史。
- 团队模型与工具循环已经迁入 Electron 主进程原生 Execution Adapter；团队窗口关闭后，任务仍由托盘主进程按 Worker 租约、心跳和检查点继续执行。
- 渲染窗口只提交任务和控制命令并读取任务投影；重新打开团队窗口会合并后台工具记录与员工回复，凭据和原始模型请求不会写入账本。
- 原生 Adapter 对重复工具、长期只读路线、无文件交付、无结构化审查和偏离原始目标进行硬拦截；审查退回会追加责任修订和复审节点。
- 聊天快速跳转轨道支持悬停预览。
- 产出物按最终交付、工作文件和参考资料折叠归类；三种聊天中的文件名均可点击定位和打开。
- 团队任务面板和产出物面板支持拖动调整宽度。

### Skill 与工具

- 技能中心按“内置 Skill / 我的 Skill / Skill 商城”分类展示。
- Hermes Agent、SkillHub、SkillsMP、Skills.sh 和 Anthropic Skills 以第三方市场卡片展示并在系统浏览器打开。
- 支持通过 `SKILL.md`、GitHub 文件、技能目录或仓库地址一键安装到本机 WorkBuddy 技能目录。
- 安装包内置 76 个 Skill 规则入口，其中包含 69 个 Hermes Agent Skill、4 个基础 Skill，以及 IMA 官方 1.1.8 的总入口、知识库和笔记规则。
- 员工根据任务需要自行判断是否检索 Skill，不再强制每个任务调用。
- Skill 或工具调用失败时展示具体错误，方便重试或改用其他方案。
- 技能库会继续保留内置技能和用户安装技能；完整目录安装、依赖健康检查、损坏隔离、来源记录和一键修复已经接入。
- 单文件、GitHub 目录和 ZIP Skill 统一先写入暂存目录，完整性检查通过后再原子替换；修复失败时旧 Skill 保持可用，不会留下半更新目录。
- 支持文件读取、写入、目录检查、网页搜索和连接器工具。
- 用户明确要求“今日、最新、实时或联网搜索”时，客户端会先执行一次真实搜索再交给模型整理，不依赖模型是否自行选择工具；普通任务仍由员工按需判断。
- 联网搜索沿用 Electron/Chromium 代理，DuckDuckGo 与 Bing 双源自动重试和切换；失败时显示具体搜索源、超时或 HTTP 原因，并写入主日志。
- 资料型请求在搜索成功后会自动读取前 5 个可访问来源正文，再进入专用整理阶段，按用户要求在聊天气泡中直接交付内容和链接；不得要求用户自行打开来源、粘贴正文或提供截图。整理模型失败会保留上下文重试，最终仍失败时由客户端直接整理搜索摘要，不再只留下执行过程。
- 设置中心提供命令沙盒和三档审批策略；助手、员工私聊、团队聊天共享同一策略并显示当前状态。

### 知识库与连接器

- 连接器入口统一管理网页知识库、Obsidian、ima、QQ 邮箱、腾讯文档、企业微信、GitHub、自定义 HTTP 及 MCP 服务。
- 连接器是外部能力的统一入口，MCP 只是其中一种接入协议；IMA 当前使用“官方 Skill 规则 + 客户端原生适配器”，不是 MCP Server。
- Skill 连接器保存后由客户端读取真实说明并执行最小验证，只有真实调用成功才显示已连接；模型负责理解和编排，不能代替客户端执行或验收。
- IMA 官方 Skill 1.1.8 已完整内置；用户只需填写 Client ID 和 API Key。根规则引用的知识库、笔记子规则会统一读入，不再因验收规则位于子模块而误报缺失。
- IMA 的最小验证由 Electron 主进程直接执行：读取已关联完整 Skill 规则、注入本地凭据、调用固定官方端点并核对 HTTP 与 API 业务码；网络、超时和服务端瞬时错误自动重试，不再经过 PowerShell 或依赖模型拼接命令。
- 纯“验证连接器”请求直接返回客户端真实证据，不再调用模型二次改写，因此不会绕回 README、重复读取 Skill 或把验证工作推给用户。
- 后续外部 API 使用同一架构：能力适配器、公开规则和安全验收逻辑随安装包内置；用户 API Key、OAuth 和账号凭据只保存在本机，不进入源码、安装资源或 GitHub。
- 网页知识库可读取网页、公开文档和在线知识库正文。
- Obsidian 可原生选择 Vault，并向员工提供搜索笔记和读取笔记工具。
- 助手、员工、团队和自主任务共享“检查状态 → 准备配置 → 用户填写专属凭据 → 真实测试 → 开放调用”的连接器生命周期，不会把连接器安装误当成 Skill 安装。
- 历史 HTTP/MCP 配置升级后继续保留；真实连接测试通过前不会显示为完成。

### 真实附件与交付文件

- 助理、员工单聊和团队聊天统一支持文件选择、剪贴板粘贴与拖拽导入。
- 附件先真实写入当前聊天的独立工作区，再由员工、Skill 和工具读取，不再只传递文件名与大小占位。
- 图片同时作为视觉输入和真实文件保存；文本、代码、CSV、JSON 可直接读取。
- 支持提取 Excel、Word、PowerPoint、PDF、OpenDocument、RTF 和 EPUB 内容，长文件可分段读取。
- 其他二进制文件同样真实保存，并明确交给匹配的 Skill 或命令工具处理；失败时显示具体原因和路径。
- 产出物只展示员工实际保存成功的交付文件，不再混入聊天纪要、命令日志、附件占位或重复记录。
- 侧栏“同步”按钮可导入仓库中的脱敏员工/团队/模型配置；API Key 不随文件同步，需要在目标电脑本地回填。

### 模型稳定性与诊断

- 员工单聊失败后可按设置自动重试，默认间隔 10 秒，最多 5 次。
- 重试继续使用原聊天上下文，不会创建一段无关的新任务。
- 团队模型超时会暂停当前步骤，等待继续执行或人工处理。
- 模型诊断显示模型名称、API 地址、HTTP 状态、耗时、上下文大小和错误摘要，不显示 API Key。

### 桌面体验

- 原生 Electron 多聊天窗口，点击窗口即可置于最前。
- 提供明亮、深色、护眼、蓝色、玻璃等十套主题，深色弹窗边框与背景保持一致。
- 内置幼圆作为统一界面字体，并支持在设置中心调整全局界面字号。
- 主标题栏和设置窗口支持拖动客户端窗口。
- 员工颜色可自由选择，并自动避免与其他员工重复。
- 提供分类员工头像库，可从会所角色、24 个在线像素角色和经典头像中一键选择，也可换一批或上传自定义头像。
- 在线像素头像来自 [DiceBear Pixel Art](https://www.dicebear.com/styles/pixel-art/)，使用 `CC0 1.0` 授权；选中后保存到本地，不长期依赖外部图片地址。
- 提供多款头像框和身份牌，状态点显示空闲、工作中或掉线。
- 最小化的聊天窗口可以从应用内重新打开。

## 快速开始

### 使用安装包

正式版本均通过核心回归、包内版本核验和发布资产一致性检查。源码、交接和远端安装资产以 `main` 与对应 GitHub Release 为准。

- [直接下载 v3.13.0 安装包](https://github.com/TTflysky/sirenhuisuo/releases/download/v3.13.0/taiji-office-setup-3.13.0.exe)
- [查看 v3.13.0 发布说明](https://github.com/TTflysky/sirenhuisuo/releases/tag/v3.13.0)

本地构建的安装程序生成在：

```text
release/taiji-office-setup-3.13.0.exe
```

可以直接覆盖安装旧版本。应用数据保存在用户目录，正常覆盖安装不会删除员工、团队、聊天和模型配置。

安装包目前未签名，Windows SmartScreen 可能提示风险。`electron-updater` 通过 GitHub Releases 检查更新，发现新版本后在后台下载，并由用户确认重启安装。

### 本地开发

```bash
git clone https://github.com/TTflysky/sirenhuisuo.git
cd sirenhuisuo
npm install
npm run dev
```

另开一个终端启动 Electron：

```bash
npm start
```

### 本地测试与大版本发布

补丁版本（例如 `0.31.1`）只在本地升级版本、构建安装包并安装验收，不运行发布流程，也不上传 GitHub。功能大版本（例如 `0.32.0`）在安装验收通过后，再提交并推送 `main`，最后运行：

```powershell
npm.cmd run publish:release
```

另一台电脑接手大版本时运行 `npm.cmd run sync:project`。发布命令自动完成回归、Windows 打包、推送、Release 三件套上传及远端 SHA-256 校验；本地测试只使用 `npm.cmd run dist:win` 和 `npm.cmd run verify:package`。

### 构建与打包

```bash
npm run build
npm run lint
npm run dist:win
```

Windows 打包脚本会在项目构建缓存中准备官方便携 Node 20.18.3，并在生成安装器后自动核对包内版本、入口、连接器适配器和 IMA 规则；不要绕过脚本直接运行 `electron-builder`。

## 模型配置规则

### 全局默认模型

在设置中的模型库添加接口，并选择“全局激活模型”。未开启独立配置的员工都使用该模型。

### 助理模型

助理可以选择自己的模型。助理模型只影响章北海助理，不会覆盖员工配置。

### 员工独立模型

编辑员工并开启“独立模型配置”后，可以：

1. 引用模型库中的已有模型。
2. 手动填写服务商、API 地址、API Key 和模型名。

团队执行时，每一步都会解析该员工的有效模型，因此一个团队可以同时使用 DeepSeek、OpenAI、千问或其他兼容模型。

## 调度流程

```text
老板发送消息
  -> 控制指令：直接暂停/汇报，不启动工具链
  -> 明确 @员工：交给指定员工
  -> 普通工作请求：助理拆解并创建任务
       -> 规划步骤
       -> 执行步骤
       -> 审查步骤
       -> 通过：归档任务和产出物
       -> 不通过：退回责任步骤修改
```


## 数据与安全

- 项目不内置任何 API Key。
- 模型、员工、团队和聊天配置主要保存在本机 `localStorage`；任务运行事实写入主进程 `task-events.jsonl`，兼容缓存和投影仍保留在本机。
- API Key 不会出现在模型诊断和员工汇报消息中。
- 工具文件操作限制在应用工作区范围内。
- 删除应用前建议自行备份重要产出物。
